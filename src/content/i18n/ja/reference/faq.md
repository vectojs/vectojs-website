# よくある質問

## アーキテクチャ

### なぜDOMではなくCanvasなのですか？

DOMはセマンティックなドキュメント構造、CSSレイアウト、成熟したアクセシビリティモデルを提供します。カスタムジオメトリや大規模で頻繁に変更されるビジュアルセットが支配的なワークロードでは、canvasは描画可能オブジェクトごとにスタイル付きDOMノードを1つ持つことを回避でき、アプリケーションに直接的なレイアウト/レンダリング制御を与えます。同時に、レイアウト、ヒットテスト、セマンティクス、パフォーマンス測定の責任をフレームワーク/アプリケーションに移します。

### すべてがCanvas上に描画されている場合、アクセシビリティはどのように機能しますか？

`Scene` は、対象となるインタラクティブエンティティに対して、実際の `<button>`、`<input>`、`<a>`、`<div>` 要素からなるアクセシビリティ投影オーバーレイ（`a11yRoot`）を維持します。これはブラウザのShadow DOM APIではありません。オーバーレイはキャンバスオフセット/CSSスケーリングと各エンティティのアフィン変換に従い、ネイティブのポインター/キーボード/フォーカスイベントを受信し、DevToolsとロールベースの自動化から可視です。アプリケーションは引き続き正しいロール、ラベル、フォーカス順序、キーボード動作、スクリーンリーダーテストを提供する必要があります。

`entity.interactive = true` を設定してシャドウノードを投影します。`getA11yAttributes()` をオーバーライドしてタグとARIA属性を制御します：

```typescript
getA11yAttributes() {
  return { tag: 'button', role: 'button', label: 'Submit form' };
}
```

### React / Vue / Svelte の統合はありますか？

まだファーストパーティパッケージとしてはありません。VectoJSは`<canvas>`要素を所有するため、WebGLライブラリとまったく同じように任意のフレームワークと統合します — キャンバスをマウントし、ライフサイクルフック（`useEffect`、`onMounted` 等）で `Scene` を初期化し、アンマウント時に破棄します。

```typescript
// Reactの例
import { useEffect, useRef } from 'react';
import { Scene } from '@vectojs/core';

export function VectoCanvas() {
  const canvasRef = useRef<HTMLCanvasElement>(null);
  useEffect(() => {
    const scene = new Scene(canvasRef.current!, { maxFPS: 60 });
    scene.start();
    return () => scene.destroy();
  }, []);
  return <canvas ref={canvasRef} />;
}
```

### 2つのSceneをタイルのようにシームレスに結合できますか？

1つの論理サーフェスとしてはできません。`Scene` は正確に1つの`<canvas>`と1つのルート`Entity`ツリーを所有します — 2つの`Scene`が座標空間を共有したり、エンティティを相互に渡したり、境界を越えてヒットテストしたりするAPIはありません。2つの`Scene`インスタンスを並べて実行する（2つのキャンバスを通常のCSSで配置する）ことは機能し、シームレスに見えますが、機能的には独立したままです：別々のレンダーループ、別々の`renderMode`/ダーティ追跡、別々のアクセシビリティ投影。エンティティを相互に関連付けて操作、変換、またはヒットテストする必要がある場合は、2つをブリッジしようとするのではなく、1つの`Scene`のツリーに配置してください。

## パフォーマンス

### VectoJSは60fpsでいくつのエンティティを処理できますか？

バックエンドに依存しないカウントはありません：パスの複雑さ、テキスト、デバイスピクセル比、アクセシビリティ投影、更新作業、GPU/ドライバー、表示割合のすべてが結果を変えます。チェックインされたヘッドレスベンチマークは現在、1,000ノードと5,000ノードの単純なCanvasエンティティをカバーしています；これは6桁のWebGL/WebGPUの主張の証拠にはなりません。ターゲットハードウェアでデモレポートを実行し、ワークロードのフレーム時間パーセンタイルを記録してください。

### `pointBackend: 'webgl'` オプションとは何ですか？

設定すると、`Scene` はメインのCanvas2Dキャンバスの上に透明なWebGL2キャンバスを重ねます。`getBatchCircle()` / `getBatchRect()` を実装する表現可能なリーフエンティティは型付きバッファに収集され、バッチ化されたWebGL描画で送信されます。一方、テキスト、画像、複雑なシェイプ、サポートされていないアフィン変換はCanvas2Dに残ります。ハードウェアのクロスオーバーポイントを測定してください；リポジトリには現在、検証済みの汎用高速化係数は含まれていません。

### `renderMode: 'onDemand'` とは何ですか？

`'onDemand'` モードでは、Sceneは `scene.markDirty()` が呼ばれたとき、またはアニメーションドライバーが進行中のときのみ描画します。静的ティックは依然としてrAFをスケジュールし、ツリーの保留中のモーションを検査しますが、エンティティの更新/レンダリング作業とGPU送信をスキップします。主に静的なUI（ダッシュボード、フォーム、メニュー）に使用します。

```typescript
scene.renderMode = 'onDemand';
entity.on('click', () => {
  entity.animate({ x: entity.x + 50 }, 300); // 自動的にダーティをトリガー
});
```

### Node.js / ヘッドレスでテストするとFPSが低いのはなぜですか？

ヘッドレスChromeはしばしばソフトウェアラスタライザーを使用し、異なるスケジューリング/vsync動作を持ちます。そのFPSは同じ環境での回帰比較には有用ですが、下限値やユーザーのGPUの予測としては使えません。ターゲットのブラウザとハードウェアで測定してください。

> [!TIP]
> Nexusデモの**レポートのエクスポート**ボタンを使用して、現在のハードウェアとブラウザで実際のGPU測定値を取得してください。それらの数値をコピーしてPRに貼り付け、ヘッドレスFPSの代わりに使用してください。

## Entity API

### `clipChildren` とは何ですか？

`clipChildren = true` を設定すると、通常の子描画がエンティティの `[0,0]–[width,height]` ボックスにクリッピングされます。これが `ScrollView` がオーバーフローを実装する方法です。CanvasRendererとSVGRendererは変換されたクリップを保持します。ThreeRendererはクリップの変換されたワールドAABBを使用してシザー矩形を交差させるため、回転/せん断されたクリップは軸に平行な近似になります。別個のWebGLポイントレイヤーとWebGPUパーティクルオーバーレイに昇格されたプリミティブは、親レンダラーのクリップスタックによってクリッピングされません。

### `a11yFullViewport` とは何ですか？

通常、シャドウDOMノードは `entity.interactive && entity.width > 0` の場合にのみ投影されます。Sceneビューポート全体をカバーするエンティティ（無限キャンバスグラフ、全画面ジェスチャ認識器）には意味のあるバウンディングボックスがありません。`a11yFullViewport = true` を設定すると、すべての他のシャドウノードの背後にSceneサイズのシャドウノードが作成されます；投影ルートはその論理ボックスをキャンバスのCSSボックスにマッピングします。

### 私の `Entity.update()` アニメーションが期待の2倍の速さです — なぜですか？

> [!CAUTION] > `Entity.update(dt, time)` は **dtをミリ秒** で受け取ります。秒ではありません。これは最も一般的なVectoJSの落とし穴です。60fpsでの `dt` は約16.7であり、0.017ではありません。

秒を使用する物理ライブラリから移植する際のよくある間違い：

```typescript
// 間違い：msを秒として扱う → 1000倍速い
this.x += velocity * dt;

// 正しい：秒に変換するか、ms単位を使用
this.x += velocity * (dt / 1000);
```

スプリング物理（`SpringPhysics`、`ScrollView`）は内部的に `dt / 1000` を使用してシミュレーションを実行する前に変換します。

### `emit()` と `dispatchEvent()` の違いは何ですか？

- `entity.emit(event, payload)` — エンティティ自身の**バブルフェーズ**リスナーのみを発火します。ツリー探索はありません。これはコンポーネント内部のパスです（例：フォームコントロールが自身の `change` を発火）。
- `entity.dispatchEvent(event)` — 完全なDOM風の**キャプチャ＋バブル**探索を実行します：キャプチャはルート→ターゲット、バブルはターゲット→ルート。これが `Scene` がポインターイベントをディスパッチする方法です。

## カスタマイズ＆アニメーション

### VectoJSのカスタマイズはどこまで可能ですか — スプラッシュスクリーンやトランジション効果はできますか？

はい。アニメーション可能なすべてのプロパティ（`x`、`y`、`scaleX`、`scaleY`、`rotation`、`opacity`）は、`TweenDriver`（曲線ベース、組み込みの`Easing`セットまたはカスタム関数から）または `SpringDriver`（物理ベース、設定可能な`stiffness`/`damping`/`mass`）で駆動できます。特にパーティクル主体のエフェクトについては、`ComputeParticleEntity` を `particleBackend: 'webgpu'` で使用すると、原点へのスプリング力、マウス反発、速度クランプ、エッジバウンス、専用の**爆発力**パラメータ（`triggerExplosion(x, y, force)`）を備えたコンピュートシェーダーが実行されます — バースト/スプラッシュ効果はファーストクラスのプリミティブであり、トゥイーンで偽装する必要があるものではありません。CPUフォールバック（`updateCPU`）は、WebGPUが利用できない場合に同じ力モデルをミラーリングします。

### `Entity` の形状はどのように定義されますか — 五角形、楕円、不規則な多角形にできますか？

はい、形状は実際には2つの独立したオーバーライド可能な関心事です：

- **視覚的形状**：`render(renderer)` は `IRenderer` のベクトルパスプリミティブ（`moveTo`、`lineTo`、`bezierCurveTo`、`arc`、`closePath`）を通じて描画します — 手書きのCanvas2D/SVGパスが使用するのと同じプリミティブなので、任意の多角形、楕円、曲線アウトラインが描画可能です。`SplineEntity` は組み込みの例です：3次多項式曲線をベジェセグメントに変換してレンダリングします。
- **ヒットテスト形状**：`isPointInside(globalX, globalY): boolean` は基底 `Entity` クラスで `abstract` です — すべての具象エンティティが独自のロジックを提供します。軸に平行なバウンディングボックスを必要とする（またはデフォルトとする）ものはありません；五角形の `isPointInside` は実際のポイントインポリゴン計算を行い、楕円は二次形式チェックを行うなどが可能です。

2つは別々のメソッドであるため、シェイプのクリック可能領域は描画されたシルエットと正確に一致する必要はありません（小さなシェイプの大きめのタッチターゲットに便利）。

### テキストとコンポーネントは異なるデバイスやブラウザズームレベルに適応しますか？テキストリサイズは完全に適応的ですか？

メカニズムは存在しますが、デフォルトで自動というよりは明示的です：

- **HiDPI**：`CanvasRenderer` は構築時と `resize()` 時に `window.devicePixelRatio` を読み取り、キャンバスのバッキングストアを適宜スケーリングします — Retina/HiDPIディスプレイは追加のアプリケーションコードなしで鮮明にレンダリングされます。
- **ブラウザズーム**：ほとんどのブラウザはズーム時に実効的な `devicePixelRatio` を変更し、`window` の `resize` イベントを発火します。`Scene` は既にこれをリッスンし、レンダラーの `resize()` を呼び出して応答します。
- **テキストリフロー**：`LayoutEngine.setMaxWidth()` は特にこのための安価な「ホットパス」として設計されています — 最後のコールド `prepare()` パスからキャッシュされた既に測定済みの `PreparedText` を再利用し、再セグメント化や再測定ではなく行分割のみをやり直します。独自のリサイズハンドラーからこれを呼び出して、任意の新しい幅でテキストを安価にリフローさせます。

つまり：適応的でリサイズが安価なレイアウトのためのプリミティブは存在し、UIコンポーネントによって内部的に使用されていますが、生のカスタム `Entity` は「無料で」リフローしません — 任意の即時モードレンダラーでキャンバスリサイズを配線するのと同じように、リサイズハンドラーを該当する `setMaxWidth`/layout 呼び出しに自分で配線します。

### VectoJSのアニメーションモデルはCSSアニメーションとどう違いますか？すべてがレンダリング前に事前計算されますか？

いいえ — 何も事前にキーフレームにベイクされません。`TweenDriver.tick(dtMs)` と `SpringDriver.tick(dtMs)` はリアルタイム積分器です：各フレーム、事前計算されたタイムラインからではなく、最後のフレームからの_実際の_経過時間から進行します。`SpringPhysics`（`SpringDriver` の背後にあるエンジン）は、固定サブステップでライブオイラー積分を行い、バックグラウンドタブが戻ったときに大きな `dt` に対して安定性クランプを適用します。

実際の違いは、アニメーションの途中でターゲットを変更したときに現れます：スプリング上の `driver.retarget(to)` は現在の値と速度を保持し、新しいターゲットに向けて滑らかに積分を続けます — スナップも再起動もありません。途中でターゲットが変更されるCSSトランジション/アニメーションは通常、再起動またはジャンプします。これは、事前に決定された曲線に沿って補間するのであって、フレームごとに物理をシミュレーションしているわけではないからです。

### コンポーネントのデフォルトのスプリング/慣性アニメーションを無効にしたり、標準トランジションに変更したりするにはどうすればよいですか？

デフォルトでは、VectoJSのスクロール可能コンポーネント（`ScrollView` や `VirtualList` など）とプロパティは、スムーズなトランジションのためにスプリングベースの物理（`'spring'`）を使用します。これらのアニメーションを無効にしてスナップ動作にしたり、標準のcubic-bezierトランジション（`easeOutCubic` など）に切り替えるには、3つの主なアプローチがあります：

#### 1. ターゲットエンティティのトランジション設定を変更

すべての `Entity` は `setTransition` メソッドを公開します。ターゲット要素で `setTransition` を呼び出し、カスタムの `duration`（ミリ秒）と `easing` 関数でデフォルトのスプリングトランジションをオーバーライドするか、完全に無効にします：

```typescript
// バウンスしない高速トランジションに変更（easeOutCubicなど）
entity.setTransition({
  y: { duration: 120, easing: 'easeOutCubic' },
});

// アニメーションを完全に無効にする（瞬時スナップ）
entity.setTransition({
  y: null, // トランジションドライバーをクリア
});
```

#### 2. スプリングを介さずに即座に位置をスナップ

設定されたトランジションをトリガーせずに（スプリングを完全にバイパスして）エンティティを即座に移動するには、`setImmediate` メソッドを使用します：

```typescript
// 位置を即座にターゲットにスナップ
entity.setImmediate('y', targetY);
```

#### 3. モバイルスクロールのためのCanvas物理のバイパス

モバイルユーザーがCanvasシミュレーションのスプリングではなくネイティブのモメンタムスクロールを期待する全画面ページでは、タッチジェスチャをブラウザのビューポートに転送します：

1. Canvasにタッチリスナーをバインドして、タッチドラッグのデルタをネイティブウィンドウスクロールに変換：

   ```typescript
   let touchStartY = 0;
   canvas.addEventListener(
     'touchstart',
     (e) => {
       if (e.touches && e.touches[0]) touchStartY = e.touches[0].clientY;
     },
     { passive: true },
   );

   canvas.addEventListener(
     'touchmove',
     (e) => {
       if (e.touches && e.touches[0]) {
         const touchY = e.touches[0].clientY;
         window.scrollBy(0, touchStartY - touchY);
         touchStartY = touchY;
       }
     },
     { passive: true },
   );
   ```

2. `window` の `"scroll"` イベントをリッスンし、`setImmediate` または高速イージングトランジションを使用してスクロール位置をレンダリングコンテナに同期：

   ```typescript
   window.addEventListener('scroll', () => {
     mainScroll.y = -window.scrollY; // または mainScroll.setImmediate('y', -window.scrollY);
   });
   ```

## UI コンポーネント & Devtools

### devtoolsは何を提供し、デバッグにどのように役立ちますか？

`@vectojs/devtools` はページ内インスペクターです — VectoJSでレンダリングされたパネルで、以下を提供します：

- Virtual Math Treeのライブツリービュー（エンティティタイプ、ジオメトリ、アクティブなアニメーションのバッジ付き）
- ワンショットエンティティピッキング（キャンバス上のエンティティをクリックしてツリーで選択）
- ワールド変換読み出し（完全な祖先チェーン後に実際に計算された位置、スケール、回転）
- 選択したエンティティのキーボードナッジ編集
- 選択したエンティティのワールド境界を表示するホストページオーバーレイハイライト

`Scene` は読み取り専用の `rootEntity`/`overlayRootEntity` アクセサーを公開しており、このようなツールが特権的内部アクセスを必要とせずにツリーを走査できます。

### VectoJSのネイティブUIコンポーネントを使用する際の注意点は何ですか？

コンポーネントセットの監査から直接得られたいくつかの知っておくべきパターン：

- **`entity.id` の一意性はあなたの責任です。** エンジンはそれを強制しません。アクセシビリティ投影（`Scene` はエンティティIDでシャドウDOMノードをキー付け）と、IDでエンティティをインデックスする独自のコード（例：`SpatialHashGrid`）にとって最も重要です — `Map` のキーを選ぶのと同じ方法でIDを選んでください。
- **別のエンティティにリスナーをアタッチするコンポーネントは `destroy()` する必要があります。** `Tooltip`、`Popover`、および同様の「ターゲットにアタッチする」コンポーネントは、ハンドラーを保存し、`destroy()` で削除します — コンポーネントが不要になったら常に呼び出し、手動で追加したリスナーを削除するのと同じようにしてください。
- **`interactive = true` は無料ではありません。** 設定すると、そのエンティティに実際のシャドウDOMノードが投影されます。ボタン、リンク、フォームコントロールには問題ありません；リーフエンティティの非常に大きなコレクションでは避けてください。`GridTextEntity` は、例えば、スケールで文字ごとにシャドウノードを投影しないように、グリッド全体で明示的に `interactive` を無効にしています。
- **カスタムドラッグベースのコンポーネントは、組み込みのポインターキャプチャパターンに従うべきです。** `Slider` などは `pointerdown` で `setPointerCapture()` を呼び出し（a11y投影要素を介して）、これによりコンポーネントのビジュアル境界を超える高速ドラッグも追跡を維持できます。独自のドラッグ可能コンポーネントを構築する場合は、`pointermove`/`pointerleave` のみに依存するのではなく、同じパターンに従ってください。`pointercancel` をロールバックパスとして処理し、ブラウザの中断がドラッグまたは選択トランザクションをアクティブのまま残さないようにしてください。

## アクセシビリティ & 自動化

### Playwrightの `page.getByRole()` で動作するようにコンポーネントを作るには？

`getA11yAttributes()` から正しいタグとロールを返します：

```typescript
// アクセシブルなボタン
getA11yAttributes() { return { tag: 'button', role: 'button', label: 'Send' }; }

// アクセシブルなリンク
getA11yAttributes() { return { tag: 'a', role: 'link', label: 'Home', href: '/' }; }

// アクセシブルなテキストフィールド
getA11yAttributes() { return { tag: 'input', inputType: 'text', placeholder: 'Search…' }; }
```

組み込みコンポーネント（`Button`、`Input`、`Link` など）はこれを自動的に行います。

### シャドウノードの位置がおかしい — エンティティがオフセットされている

2つのよくある原因：

1. **キャンバスの親が `position: relative` ではない** — `Scene` はすべてのフレームでこれを自動的に適用しますが、シーン開始後に別のCSSルールが `position: static` を強制すると、絶対配置されたシャドウノードが間違った包含ブロックに対して相対的にオフセットされます。
2. **`a11yOffsetX` / `a11yOffsetY`** — 以前に回避策としてこれらを設定した場合、まずそれらを削除して、基礎となる位置が実際に正しいかどうかを確認してみてください。

`SceneOptions` で `debugA11y: true` を有効にすると、各シャドウノードの上に半透明のハイライトボックスが表示されます：

```typescript
const scene = new Scene(canvas, { debugA11y: true });
```

## WebGPU パーティクル

### `ComputeParticleEntity` が何も表示しません — 何が問題ですか？

最も一般的な原因：

1. **`initRandomParticles()` が呼び出されていない** — パーティクルデータを初期化しないと、すべての位置が `(0,0)` でサイズが `0` になります。
2. **WebGPUが利用できない** — シーンは失敗したWebGPUリクエストをログに記録し、CPU/Canvas2Dパスにフォールバックします；`particleBackend: 'webgpu'` が設定され、ブラウザがWebGPUをサポートしていることを確認してください。
3. **キャンバスサイズが `0×0`** — 最初のフレームの前に `scene.resize(w, h)` を呼び出すか、キャンバスに寸法があることを確認してください。

### CPUフォールバックはどのように機能しますか？

WebGPUが利用できない（または失敗する）場合、`Scene` はレンダリングされるフレームごとに `entity.updateCPU(dt, mouseX, mouseY, width, height)` を呼び出し、`fillCircle` を通じてパーティクルを描画します。フォールバックはスプリング/反発/爆発/速度/バウンスモデルをミラーリングしますが、CPU/GPUの数値パスとスループットは同一であるとは保証されません。ターゲットデバイスでの測定からパーティクル数を選択してください。

### GPUからパーティクル位置を読み戻せますか？

直接はできません — パーティクル状態はWebGPUストレージバッファにあります。読み戻すには `copyBufferToBuffer` + `mapAsync` のラウンドトリップを発行する必要があり、GPUパイプラインを停止させます。代わりに、CPU上で位置が必要な場合は、CPU側の `particleData` Float32Arrayを同期させておいてください。`setOrigins()`、`setPositions()`、`setVelocities()` は `particleData` に書き込み、`needsInit = true` を設定します。これにより、次のフレームでGPUストレージバッファにアップロードされます。

> [!NOTE] > `mapAsync` + `copyBufferToBuffer` の読み戻しは意図的にパイプラインをブロックします。大規模な衝突検出や空間クエリには、CPUパスで `SpatialHashGrid` を使用して実行するか、追加のWebGPUコンピュートパスとして表現してください。

## トラブルシューティング

### `Scene` は実行されているが画面に何も表示されない

以下の順序で確認：

1. `scene.start()` が呼び出されていますか？
2. キャンバスにゼロ以外の `width` と `height` のCSSおよびHTML属性がありますか？
3. エンティティは `scene.add(entity)` でシーンに追加されていますか（単に構築されただけではありません）？
4. エンティティの `render()` メソッドは実際に `renderer.fill()` または `renderer.stroke()` を呼び出していますか？空の `render()` は何も描画しません。
5. `entity.opacity` > 0 ですか？

### スクロールホイールイベントが `ScrollView` に届かない

`ScrollView` はページスクロールを防ぐために `wheel` イベントで `e.preventDefault()` を呼び出します。シャドウノードのホイールリスナーが発火してもスクロールビューが反応しない場合、`ScrollView.add(child)` が使用されていること（コンテンツラッパーをバイパスして直接 `entity.add(child)` を使用していないこと）、およびキャンバスの親にポインターイベントをブロックする `overflow: hidden` がないことを確認してください。

### TypeScriptが `Cannot find name 'GPUDevice'` を報告する

プロジェクトに `@webgpu/types` を追加：

```bash
bun add -d @webgpu/types
```

次に `tsconfig.json` に追加：

```json
{ "compilerOptions": { "types": ["@webgpu/types"] } }
```
