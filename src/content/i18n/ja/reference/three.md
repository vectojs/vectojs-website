# `@vectojs/three`

2 つのエクスポート、2 つの異なるユースケース：

| エクスポート                                  | ユースケース                                                                                                                                                                                                                     |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`ThreeAdapter`](/reference/three-adapter/)   | VectoJS の `Scene` をアダプター所有または呼び出し元が指定したキャンバスにレンダリングし、`THREE.CanvasTexture` として公開し、UV レイキャスティングを介してポインタイベントを配線します。残りの Three.js シーンは変更されません。 |
| [`ThreeRenderer`](/reference/three-renderer/) | VectoJS の `Scene` の 2D レンダリングバックエンドとして Three.js を使用します — 塗りつぶし、ストローク、テキストは Canvas 2D の描画呼び出しではなく、正投影シーン内の Three.js メッシュになります。                              |

`ThreeAdapter` が一般的な方法です：3D シーンがあり、サーフェス上に浮かぶ 2D UI パネルが必要な場合 — コンストラクタ、WebXR/マルチタッチイベント処理、および完全な実例については、そのページを参照してください。`ThreeRenderer` は、すでに Three.js を使用しており、Canvas 2D フォールバックなしでハードウェアアクセラレーションによる 2D プリミティブを必要とするプロジェクト向けです — 実装された `IRenderer` メソッドとグラデーションシェーダーレイアウトについては、そのページを参照してください。

---

## インストール

```sh
bun add @vectojs/three three
```

TypeScript プロジェクトの場合は、Three.js の型を追加します：

```sh
bun add -d @types/three
```

## トラブルシューティング

### グラデーションがブレンドされず、単一色でレンダリングされる

`stroke()` はグラデーションをサポートしていません — 常に最初のカラーストップを単一色として使用します。グラデーションでペイントされた形状の輪郭効果が必要な場合は、閉じたパスで `fill()` を使用してください。

また、`createLinearGradient()` を `ThreeRenderer` から呼び出していること（`WebGLGradient` を返します）を確認し、`CanvasRenderingContext2D` から呼び出していないことを確認してください — 実装間でレンダラーグラデーションオブジェクトを混在させると、未定義の動作が発生します。

### 高 DPI ディスプレイでテキストがぼやける

コンストラクタの寸法を `window.devicePixelRatio` で**事前に乗算しないでください** — `@vectojs/core` の `CanvasRenderer` は、すでにアダプターキャンバスのバッキングストアを DPR で内部的にスケーリングしており（事前に乗算するとバッファが二重にスケーリングされ、論理レイアウト空間が歪みます）。ブラウザレベルの DPR は自動的に処理されます。

パネルのテキストがまだソフトに見える場合、原因は DPR ではなく 3D 投影です：プレーンの画面上の領域がテクスチャの解像度を超えています（カメラが近すぎるか、テクスチャサイズに対してメッシュが大きすぎます）。要求する `width`/`height` を増やしてください — これによりテクスチャの解像度が上がり、シーンにより多くの論理レイアウト領域が与えられます：

```ts
// よりシャープなテクスチャ：同じワールド空間メッシュサイズでより多くの論理＋物理ピクセル
const adapter = new ThreeAdapter({ width: 1024, height: 640 });
adapter.mesh.scale.set(3.2, 3.2 * (640 / 1024), 1); // ワールドサイズは変更なし；密度は 2 倍
```

コンストラクタの寸法をレイアウトを調整せずに 2 倍にすると、UI はパネルの 4 分の 1 を占めることになるので、位置とサイズもそれに合わせて拡大してください。

### ポインタイベントが VectoJS コンポーネントに影響を与えない

`updateIntersection()` は、入力が処理されるべきすべてのフレームで呼び出されなければなりません — DOM イベントリスナー内でのみ呼び出すだけでは不十分です。なぜなら、レイキャスターはイベント発生時の現在のカメラとメッシュの状態を必要とするからです。以下を確認してください：

1. `updateIntersection()` がレンダーループ内（または新しく設定されたレイキャスターを使用してポインタイベントハンドラー内で直接）で呼び出されていること。
2. レイキャスターのカメラがシーンのレンダリングに使用されるカメラと一致していること。
3. レイキャスト時に `adapter.mesh` が Three.js シーングラフの一部であること — 孤立したメッシュ（シーンに追加されていないもの）は交差判定されません。
