# 数学基础

VectoJS将UI渲染不是视为一系列CSS样式级联解析，而是视为一个纯粹的**几何和代数计算问题**。通过将布局、剔除、命中测试、文本换行和动画转化为形式化的数学系统，引擎完全绕过了浏览器的DOM和布局重新计算管线。

本文档详细介绍了作为VectoJS运行时基础的八个数学和工程支柱。

---

## 1. 虚拟数学树（VMT）

VectoJS不维护一个笨重的浏览器DOM节点树，而是在**虚拟数学树（VMT）**上操作。VMT是一个纯粹的**内存代数和坐标场景图**，而不是标记元素的表示。

### 纯内存代数表示

在传统UI中，布局由浏览器的重排引擎解析，该引擎计算级联盒模型并更新CSS渲染层。在VMT中，每个可视元素（一个_实体_）被表示为一个局部坐标系，通过仿射代数关系映射到其父元素：

$$\mathbf{M}\_{\text{world, child}} = \mathbf{M}\_{\text{world, parent}} \cdot \mathbf{M}\_{\text{local}}$$

视觉树不需要每个可绘制对象一个样式化的HTML节点。渲染遍历在JavaScript中组合数值变换；无障碍同步和DOM门户是独立的面向浏览器的阶段，其成本仍需测量。

### 分配感知的热路径

为了维持高渲染吞吐量，VMT的渲染遍历在遍历期间避免为每个节点分配内存。

- **线程化标量变换**：渲染遍历不是为每个节点分配一个矩阵对象，而是通过递归直接线程化六个标量变换参数，避免每帧每个节点的堆分配。
- **文本的扁平标量数组**：`LayoutResultBuffer`将布局坐标打包到预分配的连续类型化数组中，这些数组可以跨帧重用，减少布局节点的分配压力。但这并不意味着整个Scene或调用者是零分配的。

注意这不意味着什么：渲染遍历、命中测试和无障碍同步传递在运行时仍然是$O(N)$。`renderMode: 'onDemand'`跳过静态帧的绘制和实体遍历，尽管Scene继续轮询rAF并检查脏/动画状态。

## 2. 语义影子DOM（a11yRoot）

基于Canvas的UI引擎历史上饱受"黑盒"缺陷的困扰：它们对屏幕阅读器完全不可见，不能被自动化无障碍引擎审计，并且破坏了像复制粘贴或输入法编辑器（CJK IME）组合这样的原生浏览器功能。

VectoJS通过**语义影子DOM**（或`a11yRoot`）解决了这个问题。

### 主动无障碍投影

虽然VectoJS将所有图形直接渲染在单个`<canvas>`元素内部，但它维护了一个不可见的高保真**语义影子DOM**，以绝对定位的方式分层在canvas坐标空间的正上方。

```text
┌────────────────────────────────────────────────────────┐
│  语义影子DOM (a11yRoot: <button>, <input>...)           │  <-- 交互/无障碍层
├────────────────────────────────────────────────────────┤
│  WebGL / Canvas 2D 图形 Canvas 层                        │  <-- 高性能图形
└────────────────────────────────────────────────────────┘
```

对于虚拟数学树中的每个交互实体，引擎向影子根投影一个对应的语义HTML元素（例如，按钮用`<button>`，输入字段用`<input>`，链接用`<a>`）。这些DOM节点完全透明，但匹配对应Canvas元素的物理边界、嵌套顺序和交互状态。

### 测试和屏幕阅读器完整性

因为影子DOM由标准的原生HTML标签组成：

- **屏幕阅读器**：无障碍工具与原生语义标签交互，播报描述并读取状态。
- **自动化测试**：像Playwright或AI智能体这样的框架可以使用标准查询机制如`page.getByRole('button', { name: 'Submit' })`来定位和查询基于Canvas的UI组件。
- **IME输入法组合**：CJK输入方法原生工作，因为它们与影子层内的真实`<input>`标签交互，然后将组合的字符串实时流式传输到VectoJS的渲染引擎。

## 3. 仿射变换

VectoJS完全摒弃了CSS布局属性，如`absolute`、`relative`或`flex`定位。相反，虚拟数学树中每个节点的空间关系被压缩为欧几里得平面中的$3 \times 3$齐次**仿射变换矩阵**。

### 变换矩阵

实体的平移$(t_x, t_y)$、缩放$(s_x, s_y)$和旋转$\theta$（弧度）被组合成单个矩阵$M \in \text{Aff}(2)$：

VectoJS以$T \cdot S \cdot R$顺序应用局部变换：

$$M = \begin{bmatrix} s_x \cos\theta & -s_x \sin\theta & t_x \\\\ s_y \sin\theta & s_y \cos\theta & t_y \\\\ 0 & 0 & 1 \end{bmatrix}$$

平移加旋转本身是刚体运动群$SE(2)$；加上缩放（以及嵌套非均匀缩放加旋转产生的剪切）需要更一般的仿射群。

### 级联变换（矩阵乘法）

当遍历节点树时，子元素继承其父元素的坐标空间。由于矩阵乘法是可结合的，任何嵌套实体的全局变换矩阵$M_{\text{global}}$通过将父元素的累加全局矩阵与局部矩阵相乘来计算：

$$M_{\text{global}} = M_{\text{parent}} \times M_{\text{local}}$$

这在前序深度优先遍历（DFS）渲染传递期间执行。VectoJS直接在标量浮点变量上执行此操作（避免堆分配）以优化计算吞吐量：

```typescript
// 3x3变换矩阵的标量乘法
const globalX = parent.m00 * local.x + parent.m01 * local.y + parent.m02;
const globalY = parent.m10 * local.x + parent.m11 * local.y + parent.m12;
```

### 闭式反变换（克莱姆法则）

为了反向映射坐标（例如，将屏幕空间的鼠标点击或3D光线投射坐标转换回局部实体的坐标空间），VectoJS计算逆矩阵$M_{\text{global}}^{-1}$。

VectoJS使用六标量仿射矩阵的闭式逆，而不是通用的矩阵求解器：

$$M^{-1} = \frac{1}{\det(M)} \begin{bmatrix} m_{11}m_{22} - m_{12}m_{21} & m_{02}m_{21} - m_{01}m_{22} & m_{01}m_{12} - m_{02}m_{11} \\\\ m_{12}m_{20} - m_{10}m_{22} & m_{00}m_{22} - m_{02}m_{20} & m_{02}m_{10} - m_{00}m_{12} \\\\ m_{10}m_{21} - m_{11}m_{20} & m_{01}m_{20} - m_{00}m_{21} & m_{00}m_{11} - m_{01}m_{10} \end{bmatrix}$$

由于我们的齐次矩阵的第三行始终是$\begin{bmatrix} 0 & 0 & 1 \end{bmatrix}$，行列式简化为：

$$\det(M) = m_{00} \cdot m_{11} - m_{01} \cdot m_{10}$$

如果$\det(M) \neq 0$，`worldToLocal()`在恒定的算术时间内求解逆坐标并返回一个`{ x, y }`点。奇异变换返回`null`。

## 4. 冷/热拆分布局引擎

Web上的文本渲染以慢著称。在传统浏览器中，即使修改单个字符也可能在整个文档中触发大规模重排（重新计算宽度、分割单词和查询操作系统级字体缓存）。VectoJS通过**冷/热拆分布局引擎**解决了这个问题。

### 冷路径：分割和测量

文本处理的昂贵方面——分词（使用`Intl.Segmenter`进行单词边界）、BiDi（双向文本）排序以及使用canvas上下文测量字形边界——被隔离到**冷传递**中。

- 仅在实际文本内容变化时运行。
- 测量并构建一个扁平的、可缓存的布局映射。
- 结果存储在局部的、不可变的`PreparedText`表示中。

### 热路径：纯数学换行和对齐

当文本块调整大小时（例如，拖动窗口或动画化响应式布局卡片），VectoJS触发**热传递**：

- 避免所有`Intl.Segmenter`或canvas测量API查询。
- 直接从`PreparedText`映射中读取缓存的字形宽度。
- 通过缓存的进距进行数值运算来计算换行、垂直换行偏移和段落边距。

将冷准备与热定位分开，使得宽度变化可以重用分割和测量。段落记忆化还允许在追加操作期间重用未更改的前导段落。更改的段落仍然随其自身长度缩放，而Markdown词法分析仍然是文档范围的。

## 5. 文本流的集合差代数

传统Web浏览器使用复杂的CSS布局计算将文本环绕在障碍物周围（如浮动图像或内联标注）。VectoJS数学地将文本流建模为实数线上的**区间减法集论**。

### 行区间分割

对于垂直坐标$Y$和高度$H$的给定行，总换行宽度表示为一个闭区间$I_0 = [0, \text{maxWidth}]$。

如果$K$个障碍形状（`ExclusionRect`）与Y范围$[Y, Y+H]$重叠，每个障碍表示一个减法区间$E_k = [x_{s,k}, x_{e,k}]$：

<img src="/images/set-difference-intervals.svg" alt="图显示三个水平区间条：从0到maxWidth的总行区间，中间有一个障碍区间xs1到xe1，以及结果集合差为两个避开障碍的独立段" class="diagram" />

用于放置文本字形的可用段$I_{\text{allowed}}$通过计算集合差来求解：

$$I_{\text{allowed}} = I_0 \setminus \bigcup_{k=1}^{K} E_k$$

### 算法执行

引擎运行此集合差算术：

1. 收集所有与Y跨度重叠的排除区间。
2. 将重叠的排除区间合并为排序的不相交区间列表。
3. 从$[0, \text{maxWidth}]$中减去这些区间，得到有效子区间列表。
4. 将文本标记依次放入这些子区间中。

这允许复杂的排版换行作为确定性的、扁平的区间减法传递来解决，而不是递归的试错渲染。

## 6. 采样样条命中测试

传统的canvas框架通过不可见地绘制曲线并读取颜色像素来对曲线进行命中测试，或者检查点击是否位于包围曲线的矩形边界框（AABB）内。前者慢，后者非常不准确。

`SplineEntity`将每个三次段表示为$t \in [0, 1]$的贝塞尔曲线$P(t)$：

$$P(t) = (1-t)^3 P_0 + 3(1-t)^2 t P_1 + 3(1-t) t^2 P_2 + t^3 P_3$$

其中$P_0, P_1, P_2, P_3 \in \mathbb{R}^2$是控制点。

### 折线近似

当前实现将每个贝塞尔段采样为固定分辨率的`Float32Array`折线并缓存它。对于指针$C(x, y)$，它计算到每个相邻线段的平方距离，并在以下条件下接受命中：

$$d^2(C, \overline{P_iP_{i+1}}) \le \left(\frac{\text{lineWidth}}{2} + \text{hitTolerance}\right)^2$$

缓存的近似值使重复命中测试变得廉价且确定。它不是解析的五次/牛顿求解器：极高曲率的段可能在样本之间产生偏差，因此在选择`hitTolerance`时请考虑这一近似。`hitTest: 'aabb'`完全跳过细化。

## 7. 微分方程与半隐式欧拉求解器

CSS动画在固定的时间尺度上操作（$t \in [0, 1]$）。如果目标位置在途中发生变化（例如，跟随光标），贝塞尔曲线必须重新计算，导致视觉跳跃或动量损失。

VectoJS使用**常微分方程（ODE）**模拟物理质量-弹簧-阻尼系统来解决这个问题。

### 控制方程

动画值$x(t)$（位置、缩放或不透明度）向目标值$x_{\text{target}}$的运动由带阻尼的胡克定律控制：

$$m \frac{d^2x}{dt^2} + c \frac{dx}{dt} + k(x - x_{\text{target}}) = 0$$

其中：

- $m$是质量（惯性）。
- $c$是阻尼系数（摩擦）。
- $k$是弹簧刚度（吸引力）。

### 数值积分（半隐式欧拉）

为了在运行时逐步求解这个方程，VectoJS使用**半隐式欧拉积分**求解器。与显式欧拉（不稳定且累积能量误差）不同，半隐式求解器使用当前状态计算速度，然后使用_下一个_速度计算位置：

$$v_{t+\Delta t} = v_t + \frac{-k(x_t - x_{\text{target}}) - c v_t}{m} \Delta t$$

$$x_{t+\Delta t} = x_t + v_{t+\Delta t} \Delta t$$

其中$\Delta t$是帧时间步长（以秒为单位）。

因为求解器根据当前值$x_t$和速度$v_t$相对于$x_{\text{target}}$动态计算力，目标可以动态移动（例如，拖拽、鼠标悬停或响应式重排）。系统自然地适应，保持动量并以有机阻尼将元素平滑地带到静止状态。

## 8. SpatialHashGrid工具

在包含$N$个实体的场景中，内置的命中测试和视口剔除遍历是$O(N)$。这是否重要取决于实体工作和目标硬件。

VectoJS导出一个**SpatialHashGrid**，应用可以显式填充以限制局部AABB查询成本。Scene内置的`findEntityAt()`和视口剔除不会自动使用它；两者仍然遍历实体树。

### 哈希函数

坐标空间被划分为大小为$S$的单元格网格。任何实体的边界框映射到一组整数单元格坐标$(i, j) \in \mathbb{Z}^2$：

$$i = \left\lfloor \frac{x}{S} \right\rfloor, \quad j = \left\lfloor \frac{y}{S} \right\rfloor$$

这些网格坐标使用[康托尔配对函数](https://en.wikipedia.org/wiki/Pairing_function)映射到单个一维桶键，首先将负坐标折叠到非负域中：

$$x = \begin{cases} 2i & i \geq 0 \\\\ -2i - 1 & i < 0 \end{cases} \qquad y = \begin{cases} 2j & j \geq 0 \\\\ -2j - 1 & j < 0 \end{cases}$$

$$H(i, j) = \frac{(x + y)(x + y + 1)}{2} + y$$

桶存储在普通的`Map`中，而不是固定容量的表 —— 没有取模，映射随着有多少个不同的占用单元而增长。

### 复杂度降低

- **应用管理的索引**：实体移动时调用`insert(id, x, y, w, h)`，或为动态帧调用`clear()`并重建。
- **AABB查询**：`query(x, y, w, h)`访问由该框重叠的每个网格单元，并返回去重的`Set<string>`。
- _结果_：查询时间与重叠的单元格数加上返回的ID数成比例。仅当实体小而均匀分布时才接近常数；密集桶会退化到线性扫描。参见[性能指南](/learn/performance/#3-实体海交互on2复杂度灾难)。

## 数学优势总结

| 维度         | 浏览器 / DOM      | VectoJS              | 数学原理       |
| ------------ | ----------------- | -------------------- | -------------- |
| **场景图**   | HTML DOM树        | 虚拟数学树（VMT）    | 连续内存场景图 |
| **无障碍**   | 原生语义DOM       | 语义投影覆盖层       | DOM状态同步    |
| **变换**     | CSS变换/布局      | 3x3齐次矩阵          | 仿射线性代数   |
| **重排**     | 单线程重排        | 冷/热拆分布局        | 缓存单词分割   |
| **文本换行** | 重排试错          | 段区间减法           | 集合差代数     |
| **曲线选取** | 像素读取 / 宽AABB | 缓存采样折线         | 点到线段距离   |
| **动画**     | 三次贝塞尔时间线  | 质量-弹簧-阻尼求解器 | 二阶ODE积分    |
| **剔除**     | 浏览器渲染启发式  | 可选局部AABB边界     | 变换AABB重叠   |
