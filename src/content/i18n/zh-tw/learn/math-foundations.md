# 數學基礎

VectoJS 將 UI 渲染視為純粹的**幾何與代數計算問題**，而非一系列 CSS 樣式級聯解析。透過將布局、剔除、命中測試、文字換行和動畫轉換為正式的數學系統，引擎完全繞過了瀏覽器的 DOM 和布局重新計算管線。

本文詳細說明了作為 VectoJS 執行環境基礎的八個數學與工程支柱。

---

## 1. 虛擬數學樹 (VMT)

VectoJS 不維護一個龐大的瀏覽器 DOM 節點樹，而是操作**虛擬數學樹 (Virtual Math Tree, VMT)**。VMT 是一個純記憶體中的**代數與座標場景圖**，而非標記元素的表示。

### 純記憶體代數表示

在傳統 UI 中，布局由瀏覽器的重排引擎解析，計算級聯盒模型並更新 CSS 渲染層。在 VMT 中，每個視覺元素（一個*實體*）被表示為一個局部化座標系統，透過仿射代數關係映射到其父元素：

$$\mathbf{M}\_{\text{world, child}} = \mathbf{M}\_{\text{world, parent}} \cdot \mathbf{M}\_{\text{local}}$$

視覺樹不需要為每個可繪製物件建立一個帶樣式的 HTML 節點。渲染遍歷在 JavaScript 中組合數字變換；無障礙同步和 DOM 入口是獨立的瀏覽器導向階段，其成本仍需衡量。

### 感知分配的熱路徑

為了維持高渲染吞吐量，VMT 的渲染走訪避免了在遍歷期間為每個節點進行分配。

- **純量變換線程化**：渲染走訪不為每個節點分配矩陣物件，而是直接透過遞迴傳遞六個純量變換參數，避免了每幀每個節點的堆積分配。
- **文字的純量陣列**：`LayoutResultBuffer` 將布局座標打包到預先分配、連續的 TypedArray 中，可在多個幀之間重用，減少布局節點的分配壓力。這並不代表整個 Scene 或呼叫者為零分配。

請注意，這*並不*意味著：渲染走訪、命中測試和無障礙同步傳遞在執行時仍然是 $O(N)$。`renderMode: 'onDemand'` 會跳過靜態幀的繪製和實體遍歷，儘管 Scene 會繼續輪詢 rAF 並檢查髒狀態/動畫狀態。

## 2. 語意陰影 DOM (a11yRoot)

基於畫布的 UI 引擎歷來存在「黑箱」缺陷：它們對螢幕閱讀器完全不可見，無法被自動化無障礙引擎審計，並且破壞了複製貼上或輸入法編輯器 (CJK IME) 組合等瀏覽器原生功能。

VectoJS 透過**語意陰影 DOM**（或稱 `a11yRoot`）解決了這個問題。

### 主動無障礙投射

雖然 VectoJS 將所有圖形直接渲染在單一 `<canvas>` 元素內部，但它維護了一個不可見、高保真的**語意陰影 DOM**，以絕對定位方式分層在畫布座標空間的正上方。

```text
┌────────────────────────────────────────────────────────┐
│  語意陰影 DOM (a11yRoot: <button>, <input>...)         │  <-- 互動/無障礙層
├────────────────────────────────────────────────────────┤
│  WebGL / Canvas 2D 圖形畫布層                          │  <-- 高效能圖形
└────────────────────────────────────────────────────────┘
```

對於虛擬數學樹中的每個可互動實體，引擎會將對應的語意 HTML 元素（例如按鈕對應 `<button>`、輸入欄位對應 `<input>`、連結對應 `<a>`）投射到陰影根節點。這些 DOM 節點完全透明，但與對應畫布元素的物理邊界、巢狀順序和互動狀態相匹配。

### 測試與螢幕閱讀器完整性

由於陰影 DOM 由標準的原生 HTML 標籤組成：

- **螢幕閱讀器**：無障礙工具與原生語意標籤互動，朗讀描述並讀取狀態。
- **自動化測試**：Playwright 等框架或 AI 代理可以使用標準查詢機制（如 `page.getByRole('button', { name: 'Submit' })`）來定位和查詢基於畫布的 UI 元件。
- **IME 組合**：CJK 輸入法能原生運作，因為它們與陰影層中的真實 `<input>` 標籤互動，後者再將組合後的字串即時串流至 VectoJS 的渲染引擎。

## 3. 仿射變換

VectoJS 完全放棄了 CSS 布局屬性，如 `absolute`、`relative` 或 `flex` 定位。取而代之的是，虛擬數學樹中每個節點的空間關係被壓縮為歐幾里得平面上的一個 $3 \times 3$ 齊次**仿射變換矩陣**。

### 變換矩陣

一個實體的平移 $(t_x, t_y)$、縮放 $(s_x, s_y)$ 和旋轉 $\theta$（弧度）被組合成一個單一矩陣 $M \in \text{Aff}(2)$：

VectoJS 以 $T \cdot S \cdot R$ 的順序應用局部變換：

$$M = \begin{bmatrix} s_x \cos\theta & -s_x \sin\theta & t_x \\\\ s_y \sin\theta & s_y \cos\theta & t_y \\\\ 0 & 0 & 1 \end{bmatrix}$$

僅平移加上旋轉即為剛體運動群 $SE(2)$；加上縮放（以及由巢狀非均勻縮放加旋轉產生的剪切）則需要更一般的仿射群。

### 級聯變換（矩陣乘法）

在遍歷節點樹時，子節點繼承其父節點的座標空間。由於矩陣乘法具有結合性，任何巢狀實體的全局變換矩陣 $M_{\text{global}}$ 通過將父項累積的全局矩陣與局部矩陣相乘來計算：

$$M_{\text{global}} = M_{\text{parent}} \times M_{\text{local}}$$

這是在前序深度優先遍歷 (DFS) 渲染傳遞期間執行的。VectoJS 直接在純量浮點數變數上執行此操作（避免堆積分配）以優化計算吞吐量：

```typescript
// 3x3 變換矩陣的純量乘法
const globalX = parent.m00 * local.x + parent.m01 * local.y + parent.m02;
const globalY = parent.m10 * local.x + parent.m11 * local.y + parent.m12;
```

### 閉式逆變換（克萊姆法則）

為了反向映射座標（例如，將螢幕空間的滑鼠點擊或 3D 光線投射座標轉換回局部實體的座標空間），VectoJS 計算逆矩陣 $M_{\text{global}}^{-1}$。

VectoJS 使用六純量仿射矩陣的閉式逆，而非通用矩陣求解器：

$$M^{-1} = \frac{1}{\det(M)} \begin{bmatrix} m_{11}m_{22} - m_{12}m_{21} & m_{02}m_{21} - m_{01}m_{22} & m_{01}m_{12} - m_{02}m_{11} \\\\ m_{12}m_{20} - m_{10}m_{22} & m_{00}m_{22} - m_{02}m_{20} & m_{02}m_{10} - m_{00}m_{12} \\\\ m_{10}m_{21} - m_{11}m_{20} & m_{01}m_{20} - m_{00}m_{21} & m_{00}m_{11} - m_{01}m_{10} \end{bmatrix}$$

由於我們齊次矩陣的第三行始終為 $\begin{bmatrix} 0 & 0 & 1 \end{bmatrix}$，行列式簡化為：

$$\det(M) = m_{00} \cdot m_{11} - m_{01} \cdot m_{10}$$

如果 $\det(M) \neq 0$，`worldToLocal()` 在恆定算術時間內求解逆座標，並返回一個 `{ x, y }` 點。奇異變換返回 `null`。

## 4. 冷/熱分離布局引擎

網頁上的文字渲染以緩慢聞名。在傳統瀏覽器中，即使修改單一字元也可能觸發整個文件的大規模重排（重新計算寬度、分割單詞和查詢作業系統級別的字型快取）。VectoJS 透過**冷/熱分離布局引擎**解決了這個問題。

### 冷路徑：分割與測量

文字處理中昂貴的部分——分詞（使用 `Intl.Segmenter` 進行字詞邊界解析）、BiDi（雙向文字）排序以及使用畫布上下文測量字形邊界——被隔離到**冷傳遞**中。

- 僅在**實際文字內容變更時**執行。
- 測量並構建一個扁平的、可快取的布局映射。
- 結果儲存在局部化、不可變的 `PreparedText` 表示中。

### 熱路徑：純數學換行與對齊

當文字區塊調整大小時（例如拖曳視窗或為響應式布局卡添加動畫），VectoJS 觸發**熱傳遞**：

- 避免所有 `Intl.Segmenter` 或畫布測量 API 查詢。
- 直接從 `PreparedText` 映射中讀取快取的字形寬度。
- 透過對快取的前進值進行數值運算，計算分行符號、垂直換行偏移和段落邊距。

將冷準備與熱定位分開，使得寬度變更可以重用分割和測量結果。段落記憶化也允許在附加操作期間重用未變更的開頭段落。已變更的段落仍會根據其自身長度進行縮放，而 Markdown 詞法分析仍然是文件級別的。

## 5. 文字流的集合差代數

傳統瀏覽器使用複雜的 CSS 布局計算來將文字繞過障礙物（如浮動圖片或行內標註）。VectoJS 將文字流數學建模為實數線上的**區間減法集合論**。

### 行區間分割

對於垂直座標為 $Y$、高度為 $H$ 的給定行，總換行寬度表示為一個封閉區間 $I_0 = [0, \text{maxWidth}]$。

如果 $K$ 個障礙形狀 (`ExclusionRect`) 與 Y 範圍 $[Y, Y+H]$ 重疊，則每個障礙表示一個減法區間 $E_k = [x_{s,k}, x_{e,k}]$：

<img src="/images/set-difference-intervals.svg" alt="圖表顯示三個水平區間條：總行區間從 0 到 maxWidth，中間有一個障礙區間 xs1 到 xe1，以及結果的集合差顯示為兩個避開障礙物的獨立區段" class="diagram" />

可用的文字字形放置區段 $I_{\text{allowed}}$ 透過計算集合差來求解：

$$I_{\text{allowed}} = I_0 \setminus \bigcup_{k=1}^{K} E_k$$

### 演算法執行

引擎執行此集合差運算：

1. 收集所有與 Y 跨度重疊的排除區間。
2. 將重疊的排除區間合併為排序後的互斥區間列表。
3. 從 $[0, \text{maxWidth}]$ 中減去這些區間，產生有效的子區間列表。
4. 將文字標記依序放入這些子區間中。

這使得複雜的排版換行可以被視為確定性的、扁平化的區間減法傳遞，而非遞迴試錯渲染。

## 6. 取樣樣條命中測試

傳統的畫布框架透過不可見地繪製曲線並讀取顏色像素來進行命中測試，或者檢查點擊是否位於包圍曲線的矩形邊界框 (AABB) 內。前者速度慢，後者非常不準確。

`SplineEntity` 將每個三次段表示為一條 Bézier 曲線 $P(t)$，其中 $t \in [0, 1]$：

$$P(t) = (1-t)^3 P_0 + 3(1-t)^2 t P_1 + 3(1-t) t^2 P_2 + t^3 P_3$$

其中 $P_0, P_1, P_2, P_3 \in \mathbb{R}^2$ 是控制點。

### 折線近似

目前的實作將每個 Bézier 段取樣為固定解析度的 `Float32Array` 折線並予以快取。對於指標 $C(x, y)$，它計算到每個相鄰線段的平方距離，並在以下條件下接受命中：

$$d^2(C, \overline{P*iP*{i+1}}) \le \left(\frac{\text{lineWidth}}{2} + \text{hitTolerance}\right)^2$$

快取的近似值使得重複命中測試廉價且確定性高。它並非解析式的五次/Truncated Newton 求解器：非常高曲率的段可能在樣本之間產生偏差，因此在選擇 `hitTolerance` 時要考慮到這種近似。`hitTest: 'aabb'` 則完全跳過精細化。

## 7. 微分方程式與半隱式尤拉求解器

CSS 動畫在固定的時間尺度上運作（$t \in [0, 1]$）。如果目標位置在運動途中發生變化（例如跟隨游標），則必須重新計算貝塞爾曲線，導致視覺跳躍或動量損失。

VectoJS 使用**常微分方程式 (ODE)** 模擬物理的質點-彈簧-阻尼系統來解決這個問題。

### 控制方程式

動畫值 $x(t)$（位置、縮放或不透明度）向其目標值 $x_{\text{target}}$ 的運動由帶阻尼的虎克定律控制：

$$m \frac{d^2x}{dt^2} + c \frac{dx}{dt} + k(x - x_{\text{target}}) = 0$$

其中：

- $m$ 是質量（慣性）。
- $c$ 是阻尼係數（摩擦）。
- $k$ 是彈簧剛度（吸引力）。

### 數值積分（半隱式尤拉）

為了在執行時逐步求解此方程式，VectoJS 使用**半隱式尤拉積分**求解器。與顯式尤拉（不穩定且會累積能量誤差）不同，半隱式求解器使用當前狀態計算速度，然後使用*下一個*速度計算位置：

$$v_{t+\Delta t} = v_t + \frac{-k(x_t - x_{\text{target}}) - c v_t}{m} \Delta t$$

$$x_{t+\Delta t} = x_t + v_{t+\Delta t} \Delta t$$

其中 $\Delta t$ 是幀時間步長（以秒為單位）。

由於求解器根據當前值 $x_t$ 和相對於 $x_{\text{target}}$ 的速度 $v_t$ 動態計算力，目標可以動態移動（例如拖曳、滑鼠懸停或響應式重排）。系統自然適應，守恆動量，並以有機阻尼的方式將元素平滑地帶到靜止狀態。

## 8. SpatialHashGrid 工具

在包含 $N$ 個實體的場景中，內建的命中測試和視口剔除遍歷是 $O(N)$。這是否重要取決於實體的工作量和目標硬體。

VectoJS 匯出一個**SpatialHashGrid**，應用程式可以明確填充它以限制本地 AABB 查詢成本。Scene 內建的 `findEntityAt()` 和視口剔除不會自動使用它；兩者仍會遍歷實體樹。

### 哈希函數

座標空間被劃分為大小為 $S$ 的網格單元。任何實體的邊界框映射到一組整數單元座標 $(i, j) \in \mathbb{Z}^2$：

$$i = \left\lfloor \frac{x}{S} \right\rfloor, \quad j = \left\lfloor \frac{y}{S} \right\rfloor$$

這些網格座標使用[康托配對函數](https://en.wikipedia.org/wiki/Pairing_function)映射到單個一維桶鍵，先將負座標摺疊到非負域：

$$x = \begin{cases} 2i & i \geq 0 \\\\ -2i - 1 & i < 0 \end{cases} \qquad y = \begin{cases} 2j & j \geq 0 \\\\ -2j - 1 & j < 0 \end{cases}$$

$$H(i, j) = \frac{(x + y)(x + y + 1)}{2} + y$$

桶存在於普通的 `Map` 中，而非固定容量的雜湊表——沒有取模運算，映射會根據有多少不同的被佔用單元而增長。

### 複雜度降低

- **應用管理的索引**：在實體移動時呼叫 `insert(id, x, y, w, h)`，或為動態幀呼叫 `clear()` 並重建。
- **AABB 查詢**：`query(x, y, w, h)` 訪問該盒子重疊的每個網格單元，並返回一個去重後的 `Set<string>`。
- **結果**：查詢時間與重疊的單元數加上返回的 ID 數成正比。僅對於小型、大小相似、均勻分佈的實體接近常數；密集的桶會退化為線性掃描。請參閱[效能指南](/learn/performance/#3-實體海洋互動on2-複雜度災難)。

| **剔除**     | 瀏覽器渲染啟發式     | 可選的本地 AABB 邊界 | 變換後的 AABB 重疊 |
