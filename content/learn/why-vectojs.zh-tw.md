# 為何選擇 VectoJS

瀏覽器 DOM 是一個強大的通用文件渲染器。它非常適合文字排版、SEO 內容、原生表單和適度的互動 UI。

但當介面的行為更像場景而非文件時，它就會成為瓶頸。

## 問題所在

VectoJS 針對以下類型的介面：

- 數千個獨立動畫項目會產生過多的 DOM/樣式/布局工作；
- 布局由數學控制，而非 CSS 流動；
- 命中測試必須匹配自訂變換、曲線和座標系統；
- 同一 UI 需要在畫布、WebGL、匯出或 WebXR 環境中執行；
- 即使可見 UI 是在畫布上渲染，無障礙和自動化仍然重要。

## 與典型畫布函式庫的差異

大多數畫布函式庫提供繪圖基本元素，而將布局、事件、文字和無障礙留給應用程式處理。VectoJS 提供了更完整的執行環境堆疊。

| 層       | VectoJS                                   | 典型畫布函式庫      |
| -------- | ----------------------------------------- | ------------------- |
| 布局     | 實體樹與布局輔助工具                      | 手動                |
| 命中測試 | 每個實體的命中測試與變換轉換              | 手動                |
| 事件     | 類似 DOM 的捕獲與冒泡階段                 | 手動/僅回呼         |
| 無障礙   | 符合條件的實體的語意 DOM 投射             | 通常沒有            |
| 文字     | 布局引擎、換行、BiDi、阿拉伯文、MSDF 路徑 | 通常只有 `fillText` |
| 元件     | 表單、覆蓋層、markdown、滾動、布局        | 通常由應用定義      |
| 匯出     | 固定步進影片匯出器                        | 通常為外部          |

## VectoJS 犧牲了什麼

VectoJS 以 CSS 的便利性換取明確的控制權。你需要自行掌握更多的布局和互動模型：

- CSS 無法定位個別的畫布實體。
- 任意渲染文字的原生文字選取並非自動。
- SEO 爬蟲不會將畫布渲染的內容視為頁面文字。
- 無障礙功能透過投射啟用，但仍需要正確的標籤、角色、鍵盤行為、對比度和輔助技術測試。
- 實體遍歷、更新、語意同步和應用計算仍會消耗 CPU；畫布並不能讓所有工作變得免費。

## 何時不該使用 VectoJS

在以下情況，不要優先選擇 VectoJS：

- 你正在建立部落格、行銷頁面、文件網站或 CMS 頁面；
- UI 大部分是一般的表單和表格；
- 渲染內容的 SEO 可視性是一項硬性需求；
- 瀏覽器原生文字選取是產品的核心功能；
- 沒有自訂布局數學、動畫密度、圖形、遊戲、模擬或高實體數量的場景。

當你需要**畫布級別的視覺控制**，同時又有足夠的執行環境基礎設施來避免自行重建布局、事件、文字、無障礙和匯出功能時，VectoJS 便能大放異彩。
