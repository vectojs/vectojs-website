# 01 — Selección nativa en canvas — Paridad de dos mundos

> Un lienzo es tinta sobre un mapa de bits. La maquinaria de selección del navegador (`Range`, `Selection`, `getBoundingClientRect`, `copy`, `find-in-page`, IME) vive en DOM. VectoJS mantiene dos mundos alineados en cada cuadro: el **mundo visual** (lo que dibuja la GPU) y el **DOM mundo de selección** (lo que el navegador puede seleccionar). Este documento es el contrato entre ellos.

## 1. Por qué el canvas no tiene selección

El DOM ofrece al texto tres cosas de forma gratuita:

1. **Geometría de acceso**:`Range.getClientRects()`devuelve los cuadros diseñados por el navegador para cualquier subcadena.
2. **Fuente del portapapeles**: el evento`textContent`+`Selection.toString()`+`copy`le da al navegador una cadena lineal para serializar.
3. **Superficie de edición**:`<input>`/`<textarea>`poseen la ventana candidata IME,`compositionstart/update/end`y `selectionStart/End`.

`CanvasRenderingContext2D.fillText` escribe píxeles. El navegador no puede nombrarlos, encontrarlos ni copiarlos. `find-in-page`(Ctrl+F),`#:~:text=`enlaces de fragmentos, extensiones de traducción, modo lector, lectores de pantalla y rastreadores son todos DOM: el lienzo es invisible para cada uno de ellos. Cualquier interfaz de usuario de lienzo que desee una selección nativa debe **proyectar** una capa semántica DOM y mantenerla geométricamente indistinguible de la tinta. Una deriva de incluso 0,5 px pinta un resaltado que se desliza visiblemente fuera de sus glifos; la deriva de un carácter copia el texto incorrecto; La deriva de un grupo de grafemas rompe la ubicación del cursor para CJK y emoji.

El fallo es siempre geométrico y se agrava con la calibración. Incluso un diseño correcto por grafema variará si`getBoundingClientRect`está cuantificado (DPR), si`style.font`es un captador (Chrome 480×) o si el bloque contenedor de la superposición acelera al compositor (`fixed`vs`absolute`). La geometría, la medición y la alineación del compositor son un sistema, no tres. Dos diseños que se derivan de la misma cadena lógica pero la miden de manera diferente (ruta`measureText`diferente, saltos de línea diferentes, orden bidi diferente, tabulaciones diferentes) divergirán. La regla para todo el texto VectoJS: **compilar una vez, consumir dos veces**: un plano de geometría retenido alimenta tanto la pintura como la proyección, nunca dos diseños independientes.

## 2. Los dos mundos

```text
┌──────────────────────────────────────────────────────────────────┐
│  Visual world — canvas                                           │
│  source: string ──► LayoutEngine / prepareContentGrid            │
│       │                    │                                     │
│       │  PreparedText / PreparedContentGrid (immutable, retained)│
│       ▼                    ▼                                     │
│  flushRun / per-glyph fillText / MSDF atlas ──► pixels           │
│  at world transform (a,b,c,d,e,f) × DPR × page zoom              │
└──────────────────────────────┬───────────────────────────────────┘
                               │  same source, same plan, same epoch
                               │  same font, same advances, same x/y
                               ▼
┌──────────────────────────────────────────────────────────────────┐
│  DOM selection world — a11y / content layer                      │
│  getContentProjection() ──► ContentProjection                     │
│       │  { text, font, lineHeight, baseline, lines[], grid }     │
│       ▼                                                          │
│  Scene.syncA11y ──► per-line carriers (<span>)                   │
│       │  data-vecto-grid-cell / per-grapheme spans               │
│       ▼                                                          │
│  live DOM Range ──► Selection / copy / find / IME anchor         │
└──────────────────────────────┬───────────────────────────────────┘
                               ↕
              calibrated each frame by CanvasGeometry
              + ContentProjectionManager grid calibration
              + DPR / page zoom compensation (256 px basis)
              + font-epoch / viewport-epoch generation stamping
```

Ambos mundos derivan de **una fuente lógica** (`source: string`) y un plan de geometría retenido. Volver a segmentar la fuente para DOM crea un segundo diseño que inevitablemente no está de acuerdo: diferentes saltos de palabras en CJK, diferente orden visual bidi, diferentes tabulaciones de columnas, diferente distribución de altura de línea. La proyección nunca se repite; reutiliza las propias coordenadas del motor.

Las cuadrículas preparadas en`packages/text/src/PreparedContentGrid.ts`y la prosa en`packages/layout/src/LayoutEngine.ts`difieren solo en la unidad (celda de cuadrícula versus CSS px); ambas emiten`x/advance/level`por celda/glifo, por lo que la misma ubicación compatible con Bidi sirve para ambas.

La superposición que alberga a los portadores es en sí misma un artefacto geométrico. `CanvasGeometry.syncOverlay`(`packages/core/src/tree/scene/CanvasGeometry.ts:1`) mantiene las capas`a11yRoot`/`portalRoot`alineadas con el cuadro de lienzo CSS a través de`getBoundingClientRect`, incluida la distinción de bloque contenedor`position: fixed`vs`absolute`que decide si el desplazamiento necesita compensación JS (§4.3). El CSS`transform: scale(cssWidth/width, cssHeight/height)`de la superposición asigna coordenadas lógicas Scene al cuadro CSS; Luego, el administrador de proyección de contenido asigna coordenadas de línea lógica a eso.

## 3. Cómo VectoJS lo puentea

### 3.1 Un único plan retenido, dos consumidores

**Documentos en prosa**:`Markdown`(`packages/markdown/src/Markdown.ts`),`RichText`/`Text`(`packages/ui/src/RichText.ts`,`packages/ui/src/Text.ts`) diseñados a través de`LayoutEngine`(`packages/layout/src/LayoutEngine.ts:1`). El motor emite`LayoutResult`con`nodes: PreparedGlyph[]`, cada uno con`x / y / width / height / sourceIndex / sourceLength / isRTL / style / object`. `RichText.buildVisualLineGroups()`(`packages/ui/src/RichText.ts:668`) agrupa glifos por línea de base (`node.y + 0.8*height`), divide`sourceText`con`projectedSlice()`(`packages/ui/src/RichText.ts:506`) de modo que el objeto en línea`alt`sustituye a`U+FFFC`en el texto DOM mientras que la aritmética`sourceIndex`permanece intacto y emite`ContentProjection.lines[]`con`runs`,`perGraphemeCarriers`,`shapedPaint`,`lineHeight`,`baseline`,`font`. El nivel aproximado (`hint.textOnly`) devuelve`{ text, font, lineHeight }`sin líneas de construcción: O(1) para bloques fuera de la ventana gráfica. Canvas`render()`y`getContentProjection()`comparten el mismo objeto `result`; identidad (`===`) es la señal de invalidación (`packages/ui/src/RichText.ts:259`,`_lineGroupsCache`). `Markdown`hace lo mismo a escala de documento, componiendo`Stack`de`RichText`bloques con`contentSemanticBudgetLeft`materialización cerrada (`packages/core/src/tree/Scene.ts:600`,`DEFAULT_CONTENT_SEMANTIC_BUDGET = 256`).

**Cuadrículas similares a códigos**: terminales, editores,`CodeBlock`(`packages/markdown/src/markdown-code.ts`) se compilan a través de`prepareContentGrid()`(`packages/text/src/PreparedContentGrid.ts:prepareContentGrid`). Las entradas son`font`(CSS taquigrafía),`cellWidth`,`lineHeight`,`baseline`,`tabSize`. La salida es un`PreparedContentGrid`inmutable (`kind: 'content-grid'`,`revision`,`lines: PreparedContentGridLine[]`) donde cada`PreparedContentGridCell`lleva`sourceStart/End`,`sourceCaretOffsets`(límites legales de grafemas),`glyph`(en forma),`x`,`advance`,`level`(bidi). La configuración árabe (`ArabicShaper.ts`) y el reordenamiento bidi (`BidiResolver.ts:reorderVisual`) se ejecutan una vez; las celdas permanecen en el orden de origen lógico con el orden visual de codificación `x`. `Typography.cssLineBoxBaseline()`(`packages/text/src/Typography.ts:cssLineBoxBaseline`) deriva la línea base compatible con lienzo de`fontBoundingBoxAscent/Descent`a través del contexto adjunto compartido: el mismo valor que usan ambos mundos. La cuadrícula se devuelve como`ContentProjection.grid`y se reutiliza tanto para pintura como para proyección; pestañas, CJK/emoji amplio (`isWideCluster`), variación `VS15/VS16`, grupos ZWJ, niveles bidi, propiedad de fuente`CR/LF/CRLF`(`nextSourceStart`) comparten un plan.

**El motivo de la retención es importante.** Volver a segmentar la fuente para DOM crea un segundo diseño. Medido en `compare-pretext.ts`: el ingenuo respaldo de`0.5em`tuvo un error de hasta un 50 % (japonés), mientras que VectoJS coincidió con la verdad fundamental de DOM con un error de recuento de líneas del 0 % cuando se le dieron métricas reales. Dos diseños siempre estarán en desacuerdo; un plan elimina la pregunta.

### 3.2 Carriers por grafema — la única granularidad correcta

`Scene.syncA11y` materializa un portador invisible`<span>`por **grafema** para prosa seleccionable (`packages/core/src/tree/Scene.ts:760`ff,`perGraphemeCarriers`ruta). El ancho de cada portador es el avance del grafema **aislado** en la fuente real de la línea; su`left`es el ancho del prefijo formado en ese índice menos el desplazamiento lógico acumulado. Por qué por grafema:

- Los portadores más gruesos que un grafema ya fallan porque el error intraportador es **kerning**, no ajuste de cuadrícula. La combinación de CJK+latín con **dos** grafemas por portador fue de −0,582 px (`vectojs-docs/KNOWN_ISSUES.md:137`). No lineal, por grupo, ninguna corrección uniforme puede absorberlo.
- El diseño Gecko grid-fits DOM avanza a píxeles enteros del dispositivo, mientras que el lienzo`measureText`mantiene los fraccionarios: ~0,36% por carácter, acumulándose linealmente. `text-rendering: geometricPrecision`y desactivación del interletraje/ligaduras medidas **idénticas** a`auto`- sin CSS trampilla de escape (`packages/text/src/measureContext.ts:34`,`KNOWN_ISSUES.md:131`). Un portador por grafema es la solución que se envía; `Monospace`(avances uniformes) está bloqueado por completo (0 deriva, sin portadores).
- Los operadores son`position: relative`+`display: inline-block`con`left = run.x − runningLogicalX`en orden lógico DOM (`packages/ui/src/RichText.ts:584`,`Scene.ts`ruta por grafema). Nunca `absolute`: bloquea los cuadros en línea (`computed display: block`) y la serialización de texto plano según el diseño se interrumpe en cada cuadro de bloque:`innerText`produjo 16 nuevas líneas frente a 2 correctas, 0 espacios frente a 14 correctos para texto justificado (`KNOWN_ISSUES.md:190`). Flow-relative mantiene los lectores de copia, búsqueda en página y pantalla leyendo una línea como una línea. RTL/bidi comparte esta ruta; El objeto visual`x`proviene de`BidiResolver`niveles, el orden DOM sigue siendo lógico.

La excepción es la ruta rápida de `ui/Text`: una forma`fillText`por línea (la tinta incluye interletraje/ligaduras) declara`ContentProjectionLine.shapedPaint = true`(`packages/ui/src/RichText.ts:shapedPaint`). Sus transportistas utilizan deliberadamente diferencias de prefijo **con forma**: pintura que combina (§4.1). Las líneas justificadas nunca utilizan portadores por grafema; reutilizan la geometría`positionedRuns`propia del diseño (`packages/ui/src/RichText.ts:626`).

La segmentación en sí se realiza a través de`Intl.Segmenter`con`granularity: 'grapheme'`(`packages/text/src/PreparedContentGrid.ts:graphemes`,`packages/core/src/tree/Scene.ts:graphemeBoundaries`). El respaldo es un segmentador determinista a nivel de punto de código (`fallbackGraphemes`) que cubre marcas combinadas, selectores de variación (`VS15/VS16`), modificadores de emoji, teclas, indicadores regionales y ZWJ. Monospace no necesita segmentación alguna (celda = carácter;`PreparedContentGrid`todavía compatible con ZWJ para emoji en cuadrículas de celdas).

### 3.3 Proyección de grilla de contenido — la vía retenida

Los portadores de red son tramos`data-vecto-grid-cell`que transportan`data-vecto-grid-sourceStart/SourceLength/advance/x/level/caretOffsets/font/lineHeight`(`packages/core/src/tree/scene/ContentGridProjector.ts:291`). Ellos son:

- **En ventana**: solo se montan las líneas cerca de la ventana gráfica (`contentProjectionMargin`, sugerencia`minY/maxY`en`packages/core/src/tree/Scene.ts:projectedLines`). Los operadores fuera de la pantalla son`display: none`y no pueden interceptar la entrada.
- **Reutilizado** (`carrier reuse`,`#244`): un anexo transmitido reutiliza las transformaciones`scaleX`calibradas de líneas intactas en su lugar (`packages/core/src/tree/scene/ContentProjectionManager.ts:536`). Sólo las celdas de la cola reconstruida están pendientes de calibración.
- **Fuente reflejada**:`ContentGridProjector`refleja la fuente en `data-vecto-grid-font`, por lo que la calibración la lee como una cadena simple sin tocar `target.style.font`, que en Chrome se vuelve a serializar en cada lectura (`ContentProjectionManager.ts:292`, §4.4).

La selección en la cuadrícula es una instantánea como **desplazamientos de origen** (`ContentProjectionManager.ts:snapshotGridSelection`,`gridSelectionEndpointOffset`), no desplazamientos lineales DOM. `gridSelectionEndpointOffset`camina desde el`Selection.anchorNode/focusNode`en vivo hasta el`sourceStart`de la celda portadora y agrega el desplazamiento local de la celda, fijado a`sourceLength`(la ruptura final final vive en el mismo nodo de texto pero no pertenece a ninguna celda). Las compensaciones de origen son estables frente a saltos de línea, ventanas y calibración`scaleX`por celda; desplazamiento lineal 0 significa "primera línea actualmente materializada" y se mueve cuando lo hace la ventana. `gridCaretAtSourceOffset`resuelve un desplazamiento almacenado en`TextCaretPosition`escaneando`data-vecto-grid-cell`en orden lógico: primero la celda que cubre gana, el límite se resuelve hasta el final de la celda anterior (mismo signo de intercalación).

### 3.5 Tiempos de sincronización — nunca muestres al usuario un DOM a medio construir

**Por cuadro: materialización y luego calibración.** La calibración es un lote frío de dos cuadros (`ContentProjectionManager.ts:700`ff): el cuadro N crea una sonda lejana fuera de la pantalla (`left: -100000px`,`width: 100000px`,`contain: layout style paint`), el cuadro N+1 lee`Range.getBoundingClientRect().width`y escribe`scaleX`por celda (`element.style.transform = scaleX(...)`). La transmisión superpuesta de modo estable (agregar sin cambiar el diseño) cuesta una coincidencia de selector `querySelectorAll`. Dos salidas tempranas evitan la sonda por completo:`pendingCells.length === 0`(ya calibrado,`vectoGridReady`publicado a partir de una devolución de llamada de marco, nunca sincrónicamente; los operadores establecidos anteriormente en la misma tarea entregarían rectificaciones de ancho cero) y`measurements.length === 0`(cada celda pendiente tenía avance cero o estaba vacía, sellada inmediatamente).

**Costo de lectura: un diseño por recorrido, no por elemento.**`selectionPresent()`(`ContentProjectionManager.ts:selectionPresent`) memoriza una lectura`Selection.anchorNode`en`presentThisSync`(un diseño forzado por recorrido sincronizado). `releaseSelectionForRebuild`rechazos baratos cuando no existe un ancla rastreada ni una selección en vivo: la ruta de materialización masiva (cientos de bloques) no paga ningún diseño. `presentThisSync`se invalida al final de cada recorrido y se borra después de cualquier liberación o `setBaseAndExtent`.

**Estampado de generación.** La época de fuente (aumentada al cargar la fuente web, recreación `createMeasuringContext`) más`pageScaleX`(zoom del navegador, base 256 px) forman la generación de calibración (`ContentProjectionManager.ts:524`,`stamp = fontEpoch:pageScaleX.toFixed(4)`). Un aumento incrementa `calibrationGeneration`; cada`scaleX`por celda es implícitamente inválido sin tocar a los operadores. Las células llevan `data-vecto-grid-calib = generation`, por lo que la reutilización deja las líneas intactas.

**El peligro de reconstrucción.** Reemplazar los hijos de proyección mientras un usuario tiene una selección en el prefijo sin cambios lo borra: un mensaje de transmisión reemplaza sus hijos de proyección en cada fragmento agregado. `preserveSelectionAcrossRebuild`(`ContentProjectionManager.ts:preserveSelectionAcrossRebuild`) toma instantáneas de puntos finales como desplazamientos de caracteres lineales (`projectionAbsoluteOffset`) para prosa o desplazamientos de origen para cuadrículas, salta cuando un arrastre de región en blanco está activo (el navegador tiene autoridad mientras arrastra) o cuando el elemento propietario no contiene la selección, luego vuelve a resolver contra el nuevo DOM después de`rebuild()`y restaura mediante`Selection.setBaseAndExtent`. La instantánea`refocus`adyacente en`A11yProjectionManager.ts:211`hace lo mismo para `document.activeElement`; La selección no tenía equivalente hasta la solución de colapso de transmisión de `KNOWN_ISSUES.md:232`.

**Límite de virtualización.**`contentProjectionMargin`(finito) libera bloques completos fuera de la pantalla; `Infinity`los mantiene residentes (a ~137 ms por`syncA11y`en bloques de 10k). La búsqueda del navegador cubre contenido materializado; una entidad virtualizada no montada no se puede buscar: una aplicación debe mantener residentes los objetivos de búsqueda.

**Por qué el presupuesto es 256.** Tamaño comparado con dos costos medidos: crear un`Span`por bloque (~0,4 ms) frente a terminar el recorrido. A los 64 años, el tiempo total de pared fue ~6× (era `ContentGridPageScaleBasis.test.ts`) sin ganancia limitada por cuadro (`Scene.ts:595`). 256 es donde los dos objetivos dejan de intercambiarse.

**Presupuesto diferido.**`contentSemanticBudgetLeft`(`Scene.ts:600`, predeterminado 256 bloques) limita una caminata sincronizada, por lo que un documento de 10k bloques finaliza en ~285 pases, no en un fotograma interrumpido. `contentSemanticDeferred`retiene el desbordamiento; `contentViewportEpoch`garantiza un cambio de tamaño de niveles sin mover bloques. Los portadores de la cola diferida son toscos (`textOnly`) hasta que pasan; la geometría de selección se difiere con ellos, lo cual es correcto porque un bloque fuera de la pantalla no puede poseer un arrastre.

### 3.6 Puntero → caret: cómo un clic encuentra el nodo Text correcto

Los clics comienzan en la ventana gráfica (`clientX/Y`) y deben aterrizar en un`TextCaretPosition { node: Text, offset: number }`en coordenadas lógicas Scene (`Scene.ts:clientToScene`es solo para pruebas de impacto; la proyección tiene su propio inverso).

- **Líneas de documento en prosa** (`Scene.ts:nearestOffsetForPoint`): dado el nodo`Text`para una línea, enumere`graphemeBoundaries()`(el mismo`Intl.Segmenter`que §3.2), coloque un`Range`contraído en cada límite, llame a`range.getBoundingClientRect()`para obtener el cuadro de glifos propio del navegador y elija el más cercano a `distanceToRectSquared`. Caret aterriza en el borde de un grafema legal, no dentro de un grupo. `distanceToRectSquared`se prueba con los bordes de la ventana gráfica, por lo que un error fuera de la línea aún se resuelve en el punto final más cercano.
- **Celdas de cuadrícula** (`Scene.ts:gridCellCaret`,`nearestGridPositionInLine`): los datos de la celda`level/advance/x/caretOffsets`dan fracciones visuales frente a fracciones de origen. `visuallyRtl = (level & 1) !== 0`voltea `visualFraction → sourceFraction`, luego `caretIndex = round(sourceFraction × (caretOffsets.length−1))`. El mapeo es compatible con Bidi: el punto visual más a la derecha de una celda RTL es su inicio lógico. `nearestGridPositionInLine`prefiltra las celdas por`localX ∈ [x, x+advance]`para aciertos exactos, luego las más cercanas por distancia horizontal.
- **Líneas de cuadrícula bajo transformaciones afines** (`Scene.ts:clientToGridLocal`): la ruta rápida lee tres marcadores`data-vecto-grid-basis="origin/x/y"`colocados en la línea 0 (`ContentGridProjector.ts:basis markers`) y recupera el afín invirtiendo la base 2×2 (`determinant = xx*yy − xy*yx`). El respaldo invierte la CSS`transform`(`parseCssMatrix`) de la raíz del contenido y compensa la escala`canvasRect → logical`para DPR/zoom de página. El mismo umbral determinante (`1e-9`) controla ambos. Cuando la línea no está rotada/sin escala (`a>0, d>0, |b|,|c| ≤1e-9`),`Scene.ts:nearestGridPosition`omite el inverso completo y asigna`localX = (clientX − rect.left)/scaleX`para una ruta extra económica.

Los tres comparten un vocabulario:`collectTextNodes`/`projectionAbsoluteOffset`/`projectionCaretAt`(`packages/core/src/tree/scene/content-caret.ts:1`). El`affinity: 'forward' | 'backward'`de este último fija un límite desplazado al nodo de texto inicial o final: la diferencia entre restaurar una selección al final de la celda N o al inicio de la celda N+1, que es el mismo símbolo de intercalación.

### 3.7 Contrato de baseline: un número, dos renderizadores

El texto Canvas y la proyección del contenido deben usar el mismo desplazamiento de línea base dentro de un cuadro de línea CSS, o cada línea después de la primera acumula una deriva vertical (medida ~0,35 em por línea más ~6 px en la línea 0 a 24 px, fijado en CTX-0333/0334).

_ICODE000_ ( _ICODE001_ ) es la fuente única:`baseline = (lineHeight − ascent − descent)/2 + ascent`. Tres niveles:

1. **Lienzo adjunto** (`getSharedMeasuringContext().measureText('Mg').fontBoundingBoxAscent/Descent`): la misma fuente que el lienzo pintado (§4.2 precaución separada;`Typography.ts:32`). Entradas LRU 512 con clave`font\0lineHeight`(`BASELINE_CACHE_MAX = 512`), con actualización de LRU al acceder.
2. **Métricas registradas** (`getFontMetrics(family).ascenderEm/descenderEm × size`,`Typography.ts:registeredBaseline`): cuando aún no existe un lienzo o en SSR, la misma fórmula de centrado para que una fuente registrada y un navegador real coincidan. Negativo`descenderEm`volteado a positivo para que coincida con la polaridad del lienzo.
3. **Retroceso** —`lineHeight × 0.8`cuando la familia no tiene ascendente/descendente. Preserva el contrato libre determinista DOM; SSR y el navegador no están de acuerdo solo por el respaldo, no por la falta de un diseño.

Cada flujo de trabajo que centra métricas de fuentes en un cuadro de línea debe llamar a esto: `RichText.buildVisualLineGroups`, `TextEntity`,`MSDFTextEntity`(cuando los glifos se asignan 1:1 a la fuente), `ContentGridProjector`. Antes de este contrato,`TextEntity`/`MSDFTextEntity`usaban lanzamientos ad-hoc`0.8em`y`(ascender−descender)em`y fallaban en la proyección por ~6 px + 0,35 em/línea en Firefox (corregido CTX-0333/0334).

### 3.8 Cadena de métricas: el orden en que se resuelven los avances

No todos los entornos tienen un lienzo. Tres capas, consultadas en orden de preferencia por`resolveGlyphMeasurer()`(`packages/layout/src/measure.ts:resolveGlyphMeasurer`):

| Prioridad | Fuente                                             | Archivo                                                                                      | que mide                                                                                                                                           | cuando gana                                                                                                    |
| --------- | -------------------------------------------------- | -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 1         | Canvas (`createCanvasMeasurer`)                    | `packages/layout/src/measure.ts:18`                                                          | Per-grapheme `ctx.measureText(char).width` at `baseSize=100`, derived linearly (`base × fontSize/100`), cache keyed `size+family+char+bold/italic` | Navegador con lienzo: mide la fuente que realmente dibujará el renderizador, incluidos los pesos sintetizados. |

Regla de la cadena: el lienzo gana deliberadamente (comentario `measure.ts:resolveGlyphMeasurer`). Preferir métricas registradas permitiría que un registro obsoleto anulara la verdad básica en el entorno que tiene verdad básica. `EMPTY_GLYPH_ATLAS` (`packages/layout/src/LayoutEngine.ts:EMPTY_GLYPH_ATLAS`,`packages/ui/src/RichText.ts:371`) es una identidad congelada, no una`{}`nueva, por lo que la nota de párrafo del motor (`prepareRich`+`prepare`) no se invalida en cada diseño (medido 2,68×: 88 ms → 32,8 ms en 200 re-diseños de 12 párrafos, 0 → 2388 visitas).

### 3.9 Streaming y ventanas: donde la selección se encuentra con la escala del documento

`Markdown` (`packages/markdown/src/Markdown.ts:681`) compone un`Stack`de`RichText`bloques. Dos mecanismos de ventanas ortogonales interactúan con la selección:

- **`virtualizeBlocks`** (`MarkdownOptions.virtualize`,`Markdown.ts:614`,`virtualOverscan`predeterminado 800) — bloques de nivel superior cerca del montaje de la ventana gráfica; altura fuera de la pantalla como`RowHeights`(árbol Fenwick sobre `height+blockGap`). Incompatible con streaming (`createStream`/`appendMarkdown`): un documento que se virtualiza debe renderizarse completo. La persona que llama controla`setVisibleRange`cada cuadro de desplazamiento (un`ScrollView`lo hace automáticamente).
- **`tableViewportHeight`** (`MarkdownOptions.tableViewportHeight`,`Markdown.ts:652`) — virtualización de filas por tabla (`Table`virtualiza sus propias filas en un`viewportHeight`fijo). Independiente del bloque de ventanas; funciona a mitad de camino porque`Table.appendRows`se monta con pereza. Se aplica a todas las mesas, incluidas las cortas; una mesa de dos filas también está fijada a esta altura, por construcción (Table toma`viewportHeight`como `readonly`).

`Markdown.streamStats` (`Markdown.ts:951`) - contadores baratos siempre activos - distingue **transferencia** (`tokensPrefixMatched`/`tokensReturned`) del **costo del analizador** (`lexerMs`/`sourceCharsLexed`). La antigua denominación los combinó, enviando a los lectores a optimizar la ruta delta ya resuelta. El`incrementalLex`del trabajador omite la lectura del prefijo estable; las formas degradadas (dos casos `DegradeReason`) todavía pagan O(documento) por anexo:`sourceCharsLexed`la longitud del documento de seguimiento es la señal. `stablePrefixChars`es enviado por el propio`IncrementalLexCache.stableOffset`del trabajador, no resumido por respuesta (que fue O(n²) en un flujo de n fragmentos, #657).

`CodeBlock` (`packages/markdown/src/markdown-code.ts`) y visualización matemática (`MathBlock`,`packages/markdown/src/markdown-math.ts`) **no** son renderizadores de bloques delimitados por el registro (`Markdown.ts:138`). El registro recibe`(source, lang, options)`pero ambas rutas necesitan estado de instancia:`subscribeInlineMathRepaint`y`subscribeInlineMathRaster`/`subscribeInlineImageRaster`para escenas `onDemand`, más el objeto único`RichText`que permite que una fórmula alcance la selección/buscar/copiar. Las copias del registro divergieron silenciosamente (`MathBlock`construidas como`(mathRender, source, ...)`cuando la firma es`(formula, svgUri)`), rompiendo 7 pruebas (`Markdown.ts:154`). El registro es un punto de extensión para los idiomas que el paquete no implementa.

Relevancia de copia: se proyecta una celda`Table`por celda; una cuadrícula`CodeBlock`usa `PreparedContentGrid`; una fórmula`MathBlock`es texto proyectado más un nombre accesible; cada uno participa en la búsqueda/selección sólo cuando se materializa. La copia del portapapeles para una selección que abarca varios bloques es la concatenación de`projectedSlice`por bloque; la sustitución en línea SVG/Math alt según §3.1 mantiene las compensaciones intactas.

### 3.10 Baselines y por qué existen

`forge/baselines/*` y`vectojs-docs/forge/baselines/*`fijan los números que cita este documento para que un cambio futuro pueda dividirse en dos en lugar de volver a medirse a partir de rumores. Concretamente: la tabla base de 256 px (1/2/4/10/100/1000 px → 0.9921875…1.0), el triple`measureText('MMMMMMMMMM')`separado versus adjunto para`monospace/serif/sans-serif`en Firefox (`measureContext.ts:1`), la desalineación de desplazamiento versus renderizado de 64.8 px (661 cuadros / 630 px de desplazamiento suave), el costo del getter`style.font`de 288/290 ms (Chrome frente a 0,6 ms Firefox) y la tasa de aciertos de la nota de bloque`Stack`+`RichText`(0 → 2388 después de `EMPTY_GLYPH_ATLAS`). `KNOWN_ISSUES.md`registra el rechazo por grafema (dos grafemas → −0,582 px en CJK+latín mixto) y el error de texto plano del portador`absolute`(16 nuevas líneas frente a 2, 0 espacios frente a 14). Cuando un nuevo motor o host informa una brecha diferente, vuelva a ejecutar el arnés en el`DPR/ZOOM`anclado y compárelo con la confirmación de referencia; la diferencia es si la solución es un error del visor o una regresión VectoJS. `packages/core/test/ContentGridPageScaleBasis.test.ts`es el único oráculo a nivel de unidad para la cuantificación; todo lo demás necesita un navegador con encabezado (COOP/COEP para fidelidad `performance.now`, ventana enfocada para devoluciones de llamadas del compositor; consulte la habilidad `vectojs-performance`).

## 4. Partes difíciles — con recibos

### 4.1 Deriva por kerning: avances de cadena completa vs aislados

El diseño posiciona los glifos sumando **aislado** por grafema`measureText(char).width`(`packages/layout/src/measure.ts:createCanvasMeasurer`→`getSharedMeasuringContext()`,`baseSize 100`escalado aritméticamente). La pintura permanece dentro de los 0,5 px del diseño (`packages/ui/src/RichText.ts:COALESCE_TOLERANCE_PX`):`flushRun`fusiona una ejecución en una`fillText`solo cuando`abs(measureText(runText) − sum(isolated)) ≤ 0.5`(`RichText.ts:1001`); de lo contrario, vuelve a dibujar por carácter en`node.x`. La cadena completa`measureText(text).width`incluye interletraje y el lienzo nunca se pinta. Por lo tanto, los portadores que usaban anchos de cadena completa estaban **por delante de la tinta por el delta de kerning acumulado**, hasta 5–8 px en una línea latina de 16 px con un kerning pesado de ~300 px, tanto Gecko como Blink (`KNOWN_ISSUES.md:168`).

Solución: los anchos de los portadores siguen el modelo de pintura de la línea a través de `ContentProjectionLine.shapedPaint`. Los pintores por glifo (`RichText`, núcleo`TextEntity`) obtienen avances de grafemas aislados; La ruta rápida de`ui/Text`(una`fillText`con forma por línea) declara`shapedPaint`y mantiene portadores de diferencia de prefijo con forma. Las líneas justificadas reutilizan la geometría`positionedRuns`propia del diseño y nunca tuvieron esta desviación. `logicalRuns`suma anticipos aislados vía`mctx.measureText(segment)`(`RichText.ts:598`); `positionedRuns`reutiliza`node.x/width`directamente. La ruta por grafema en`Scene.ts`refleja esta rama.

Una solución para hermanos:`RichText.logicalRuns`anteriormente usaba medidas de cadena completa por ejecución; La ruta por grafema de`Scene`midió las diferencias de prefijos de formas: misma clase, misma solución (PR #460,`@vectojs/core@1.35.1`+ `@vectojs/ui@2.16.3`).

### 4.2 Cuantización por DPR y la base de escala de página de 256 px

Los navegadores redondean`getBoundingClientRect().left`a **1/64 px del dispositivo** (`ContentProjectionManager.ts:62`,`CanvasGeometry.ts:PAGE_SCALE_BASIS_PX`). Una sonda de 1 px cuantifica a un múltiplo de 1/64; en DPR 1.1, la escala de la página recuperada era **0,9921875** (=63,5/64), donde verdadero era 1,0: un error del 0,78 % (`ContentProjectionManager.ts:68`). Cada`scaleX = advance * scale / natural`(`ContentProjectionManager.ts:717`) por celda se redujo según ese factor: paso de 18,0001 px seleccionado como 17,8624 px, dejando un espacio de **0,133 px** en cada costura CJK y 0,061 px en cada costura latina; en DPR 1.1, aterrizan en un límite de dispositivo-píxel y se pintan como una línea blanca vertical`使|用|sudo`(`ContentProjectionManager.ts:71`). Medido sobre bases 1/2/4/10/100/1000 px en la misma página:`0.9921875, 1.0, 0.998046875, 1.0, 1.0, 1.0`— cada base ≥10 px coincidió exactamente; la lectura de 1 px fue el valor atípico.

Solución: mide más de **256 px** (`PAGE_SCALE_BASIS_PX = 256`,`ContentProjectionManager.ts:85`). El peor de los casos se convierte en`1/64 / 256 = 6.1e-5`(residuo de 0,0011 px en 18 px, ~100 × por debajo de un píxel representable por el navegador) mientras permanece muy dentro del ancho de 100000 px de la sonda para que no pueda introducir una barra de desplazamiento o su propio diseño (`ContentProjectionManager.ts:80`). Oracle de prueba:`packages/core/test/ContentGridPageScaleBasis.test.ts`modela la cuantificación directamente.

Hermano: los lienzos de medición separados resuelven mal las familias genéricas en Firefox (`packages/text/src/measureContext.ts:1`). `22px monospace`independiente 109.737 vs adjunto 131.579 vs diseño 132.000; `serif`separado colapsó en el respaldo de`monospace`(−47% en `serif`, −20% en `monospace`). Solo`sans-serif`estuvo de acuerdo, razón por la cual las pruebas de solo Chromium lo ocultaron. Cada medidor debe usar`getSharedMeasuringContext()`(adjunto,`document.body`-parented, nunca `display: none`). `OffscreenCanvas`mide correctamente (132.000) pero el contrato es "mide donde pintas" — el lienzo pintado está pegado, por lo que el de medición también debe estarlo. La brecha residual de ~0,3% entre adjunto y diseño es el ajuste de red Gecko de §4.4, no esto.

### 4.3 Compositor vs hilo principal vs deriva fixed/absolute

Se compone un lienzo de ventana gráfica completa`position: fixed`contra la ventana gráfica **fuera del hilo principal**; Se presenta una superposición`absolute`sobre el documento que se desplaza. Mantenerlos juntos volviendo a derivar`top`de`parent.getBoundingClientRect()`por cuadro **renderizado** dejaba la superposición obsoleta cada vez que el desplazamiento avanzaba sin renderizar. Medido en una escena de ventana gráfica completa en vivo, desplazamiento suave real impulsado por teclas de más de 630 px: 661 fotogramas muestreados, **1 fotograma desalineado por 64,8 px** (`CanvasGeometry.ts:191`).

Solución: la superposición hereda el`position`propio del lienzo (`CanvasGeometry.ts:206`,`getComputedStyle(canvas).position`). `fixed`resuelve`left/top`contra la ventana gráfica, exactamente`canvasRect.left/top`(`CanvasGeometry.ts:222`); `absolute`mantiene la aritmética relativa a los padres con`clientLeft/scrollLeft`(`CanvasGeometry.ts:226`). Scroll entonces no necesita compensación JS; la solución **elimina** la dependencia por cuadro en lugar de sincronizar con más frecuencia. Un oyente de desplazamiento aún ejecutaría el compositor como trabajo del hilo principal. Las escrituras restantes se anotan (`OverlayGeometry: left/top/cssWidth/cssHeight/width/height/position`,`CanvasGeometry.ts:235`), por lo que un marco sin cambios no escribe nada; las asignaciones idénticas aún tocan el CSSOM y crecen con el recuento de capas superpuestas (`CanvasGeometry.ts:250`).

### 4.4 Huecos subpíxel CJK y coste de búsqueda de fuente

Después de la corrección de escala, la deriva residual es el ajuste de cuadrícula Gecko de ~0,36% (el diseño se ajusta a px de dispositivo entero, el lienzo se mantiene fraccionario):`text-rendering: geometricPrecision`**no** es una solución, medida de manera idéntica a`auto`(`packages/text/src/measureContext.ts:34`,`KNOWN_ISSUES.md:131`). La misma clase de sorpresa produjo una segunda trampa de rendimiento independiente:`style.font`es un captador taquigráfico en vivo que vuelve a serializar cada fuente escrita a mano en cada lectura. El escaneo de calibración que decía`target.style.font`una vez por celda pagó **288 ms de 290 ms (99,3%)** en Chrome, mientras que Firefox gastó 0,6 ms en el bucle idéntico: una brecha entre motores de 480× cuya única señal era el motor, no el trabajo (`ContentProjectionManager.ts:292`). Solución: los operadores almacenan una cadena`data-vecto-grid-font`simple (`ContentGridProjector.ts:291`) y`ContentProjectionManager`la lee. `contain: layout style paint`en la sonda lo aísla.

### 4.5 IME, portapapeles y el espejo editable

`Input` /`TextArea`**no** son proyecciones de contenido. Proyectan un`<input>`/`<textarea>`realmente transparente (`Site:Accessibility & Automation`§IME campos de entrada compatibles,`packages/core/src/tree/Scene.ts:a11y input mirror`,`packages/ui/src/Input.ts`/`TextArea.ts`). El navegador posee la ventana candidata IME; el lienzo refleja`value/selectionStart/selectionEnd/composition`de los eventos`input`/`change`/`compositionstart/compositionupdate/compositionend`del nodo de sombra y dibuja el cursor, el resaltado de selección y el subrayado IME por cuadro. El tamaño del nodo de sombra se dimensiona mediante`textInputStyle: { font, lineHeight, padding }`de`Entity.getA11yAttributes()`→`Scene`lo aplica con`box-sizing: border-box`mientras que el lienzo se basa en el mismo relleno y `Typography.cssLineBoxBaseline`: una línea de base, dos consumidores, sin deriva vertical entre el editor invisible y su espejo de tinta.

Durante el enfoque,`Scene`evita volver a escribir el mismo`value`sincronizado por el usuario (supresión de eco): si el estado de la aplicación proporciona un valor realmente diferente, se aplica, pero un componente controlado que reemplaza el texto debe preservar`selectionStart/End`intencionalmente o el cursor salta. `Input`es una entidad compatible con`a11yFullViewport`de una sola línea; `TextArea`es un desplazador multilínea compatible con`clipChildren`con`scrollLeft`/`scrollTop`reflejado en el lienzo: la misma ruta de superposición de transformación mundial → que cualquier otra entidad, por lo que DPR/zoom/rotación se aplican de manera idéntica.

Ruta del portapapeles:`cut/copy/paste`y`undo/redo`son nativos, a través de ese nodo oculto, para campos editables. Para texto seleccionable estático,`copy`es la serialización propia del navegador de la capa proyectada:`projectedSlice()`(`packages/ui/src/RichText.ts:506`) sustituye el`alt`de cada objeto en línea por el centinela`U+FFFC`en el espacio **fuente** para que la aritmética de`LayoutNode.sourceIndex`permanezca intacta; de lo contrario, un`alt`de cualquier longitud diferente a la otra cambiaría cada cuadro de selección posterior desplazado y desincronizado. El hermano`accessibleText()`(`RichText.ts:478`) existe para la ruta`aria-label`y deliberadamente no se usa para dividir. `SeparatorAfter`(nueva línea lógica/separador de ajuste suave preservado, `ContentProjectionLine.separatorAfter`) se fusiona en el nodo de texto final de la línea, por lo que Firefox no puede colocar parte de una selección de varias líneas en la raíz de la proyección. `Table`copia de celda,`CodeBlock`copia de cuadrícula y`MathBlock`copia de fórmula fluyen a través de la misma concatenación por bloque `projectedSlice`: en línea SVG/Math`alt`la sustitución según §3.1 mantiene las compensaciones intactas a través de los límites de los bloques.

Advertencia:`packages/devtools/src/selectionAudit.ts:119`capturó anteriormente`getSelection()`y luego llamó a`removeAllRanges`(`:157`): una auditoría que destruyó el estado del usuario. La auditoría actual (`selectionAudit.ts:102`) utiliza`Range`separado (`document.createRange()` +`selectNodeContents`+ `getClientRects`) que nunca toca `DocumentSelection`; no hay ninguna selección programática para limpiar. Deje la selección del usuario exactamente como la encontró.

### 4.6 Grafema, kerning y el hueco blanco CJK — el bug que parece un artefacto de renderizado

El artefacto`使|用|sudo`se lee como un error de GPU: una línea blanca vertical entre glifos Han adyacentes. Es un error de selección-proyección que se ve a través del ráster. La cadena es:

1.`getBoundingClientRect().left`cuantificado a 1/64 px del dispositivo a 1 px →`basisScale`0,78 % mínimo en DPR 1,1 (`ContentProjectionManager.ts:68`); 2.`scaleX = advance × basisScale / natural`0,78% bajo (`:717`); 3. cada`data-vecto-grid-cell`pintado`advance`de ancho pero cuadro de selección con un tamaño de`advance × scaleX`→ cada costura CJK 0.133 px corta (`:71`); 4. en DPR 1.1, el déficit cae exactamente en el límite de un dispositivo-píxel → el compositor deja una columna descubierta → blanca.

Las costuras latinas tienen la misma geometría (0,061 px), pero un`advance`más estrecho lo oculta. Cambiar el rasterizador, cambiar a`geometricPrecision`o deshabilitar el interletraje no hace nada: el espacio no está en la tinta sino en el`scaleX`con el que se dibuja la tinta. La prueba que lo protege es el oráculo básico a escala de página (`ContentGridPageScaleBasis.test.ts`) más el arnés con cabeza en`DPR=1.1`; El DPR 1 sin cabeza no reproduce nada.

### 4.7 La calibración no es un arreglo único — fuente, DPR y viewport fuerzan cada uno un resellado

El`scaleX`por celda es`advance × (pageScale × deviceScale) / natural`solo en el instante en que se midió. Cualquiera de las tres entradas puede cambiar sin que la entidad se mueva: una fuente web finaliza (`contentFontEpoch`golpe,`watchFontMetrics`→ época,`Typography.clearCssLineBoxMetrics`), el usuario hace zoom (escala de página a través de`getBoundingClientRect`base de 256 px,`ContentProjectionManager.ts:524`), o`devicePixelRatio`/ cambios de tamaño del lienzo (`Scene.resize`→`CanvasGeometry.effectiveDPR`→ `contentViewportEpoch`). `calibrationGeneration`(`ContentProjectionManager.ts:calibrationGeneration`) los combina en un contador, de modo que una sola comparación invalida cada celda. La falla cuando esto se pasa por alto es silenciosa: el antiguo`scaleX`permanece, los portadores tienen el ancho incorrecto y`selectionAudit`informa una desviación que crece con la longitud de la línea pero desaparece al actualizar. `data-vecto-grid-calib`es el campo a observar: cualquier celda con el sello`generation`que sobreviva a un zoom es una lectura obsoleta.

### 4.8 Cómo se mide realmente la corrección: el harness de selección

Sin cabeza (`jsdom`,`--disable-gpu`) no tiene GPU, ni compositor, ni geometría`Range`en DPR fraccional y`performance.now()`grueso a 100 µs sin COOP/COEP; no puede citar la paridad de selección. Sólo`scripts/selection-harness/harness.ts`+`drive.sh`pueden hacerlo. `harness.ts`crea un documento`Scene`+`Markdown`+`CodeBlock`real con fuente y fuente conocidas, `maxWidth`, luego`drive.sh`lanza Chrome y Firefox **con título real** en un espacio de trabajo dedicado de Hyprland en`DPR`×`ZOOM`(`--force-device-scale-factor`,`layout.css.devPixelsPerPx`,`scripts/selection-harness/drive.sh:6`) y genera un arrastre nativo a través de la misma ruta`clientToGridLocal`/`nearestOffsetForPoint`que visita el usuario. `selectionAudit.ts:1`es el oráculo:`expectedLeft/Right`de`ContentProjectionLine`geometría vs`actualLeft/Right`del DOM`Range`en vivo en **px lógico local** (DPR/zoom dividido). Matriz vacía = cada cuadro de selección rastrea sus glifos; cualquier hallazgo lleva`entityId`,`entityPath`,`line`,`leftDrift/rightDrift`para bisección.

Tres modos de falla que el arnés está diseñado para detectar: espacios justificados entre palabras, reordenamiento visual RTL/bidi + fijación`dir="ltr"`y redondeo de zoom/DPR fraccional (`scripts/selection-harness/README.md:8`). Headless DPR 1 oculta los errores de cuantificación de 256 px y el ajuste de cuadrícula Gecko de ~0,36% que se envían en DPR 1.1/1.6; ejecute el arnés en`DPR=1.5 ZOOM=0.9`así como en 1× antes de reclamar la paridad.

## 5. Invariantes que los desarrolladores deben mantener

> Cada invariante es un lugar donde dos rutas de código deben coincidir en un número y una dirección. Si no están de acuerdo, el usuario ve un espacio, un resaltado desplazado o una selección perdida, y los pases sin cabeza lo ocultan. El`file:line`es el lugar para verificar, no una sugerencia.

1. **Mida dónde pinta.** Utilice`getSharedMeasuringContext()`(`packages/text/src/measureContext.ts`) — adjunto,`document.body`-parented,`opacity: 0`en`left: -9999px`, nunca`display: none`. Nunca un lienzo separado para familias genéricas; nunca vuelva a medir`serif`/`monospace`sin el contexto de estilo del documento. `fontMetrics.ts`(`packages/text/src/fontMetrics.ts:registerFontMetrics`,`registerMSDFFontMetrics`) es el respaldo gratuito DOM (MSDFAtlas`advance`/`kerning`/`ascender/descender`), no la ruta preferida en un navegador. Después de cargar una fuente web, llame a`clearCssLineBoxMetrics()`y deje que`watchFontMetrics`cambie la época: los avances obsoletos almacenados en caché son un error de ancho de línea antes de que se involucre cualquier proyección.
2. **Un plan, dos consumidores.** Entidades tipo código:`prepareContentGrid()`una vez → mismo objeto inmutable para pintura y`getContentProjection().grid`(`packages/text/src/PreparedContentGrid.ts`). Prosa:`LayoutEngine`una vez → mismo`LayoutResult`para`render()`y`getContentProjection()`(`packages/layout/src/LayoutEngine.ts`,`packages/ui/src/RichText.ts:284`caché). Nunca vuelva a segmentar, reajustar ni tokenizar para DOM. `EMPTY_GLYPH_ATLAS`como identidad del atlas (`LayoutEngine.ts:EMPTY_GLYPH_ATLAS`) mantiene activa la nota de párrafo.
3. **Flow-portadores relativos, en orden lógico DOM.**`position: relative`+`display: inline-block`con`left = run.x − runningLogicalX`(`packages/ui/src/RichText.ts:584`). Nunca `absolute`: bloquea y rompe el texto sin formato`innerText`/ `textContent`, la continuidad de la línea`find-in-page`y la iteración de la línea del lector de pantalla. RTL/bidi comparte esta ruta; El objeto visual`x`proviene de niveles, el orden DOM permanece lógico, por lo que`innerText`se copia en el orden de origen. `contain: layout style paint`en la sonda, no en los transportistas.
4. **Nunca elimine los portadores para un tamaño de árbol de 11 años.** Los nodos`StaticText`por carácter se leen letra por letra (consulte `xuepoo-blog/src/text-utils.ts`); La desactivación de los operadores restaura una desviación de ~2 px en Firefox. El costo del árbol es real (consulte`Site:Accessibility & Automation`§El costo escala superlinealmente: 6,4 µs → 136,9 µs/entidad a 20k), pero los operadores no son la palanca: las ventanas (`contentProjectionMargin`) y`a11yProjection: 'onDemand'`sí lo son.
5. **Los desplazamientos de origen son las únicas coordenadas de selección estables.** Los desplazamientos lineales DOM se desplazan cuando la ventana de cuadrícula o los saltos de línea cambian (`ContentProjectionManager.ts:gridSelectionEndpointOffset`). Cuadrículas instantáneas como `sourceStart + withinCell`, prosa a través de `projectionAbsoluteOffset`/`projectionCaretAt` (`packages/core/src/tree/scene/content-caret.ts`). La afinidad`forward`vs`backward`decide a qué lado del límite de una celda se fija un signo de intercalación.
6. **Respeta el modelo de pintura.**`ContentProjectionLine.shapedPaint`le dice a`Scene`qué avance usar; Las líneas justificadas reutilizan la geometría de glifo propia del diseño (`positionedRuns`,`packages/ui/src/RichText.ts:626`). Configurar`x`en una ejecución de flujo natural invierte`hasPositionedRuns`y fuerza `dir="ltr"`: correcto para justificar/RTL, incorrecto para LTR irregular (`RichText.ts:533`). Una línea irregular debe mantener`dir="auto"`para que el navegador bidis el texto en sí y el mapeo de aciertos del cursor se mantenga correcto.
7. **Heredar posición de superposición.**`CanvasGeometry.syncOverlay`(`packages/core/src/tree/scene/CanvasGeometry.ts:206`) debe reflejar`fixed`/ `absolute`; no vuelva a derivar`top`del padre por cuadro. Recuerde`OverlayGeometry`y`invalidateOverlay()`solo cuando aparezca una nueva capa (`glCanvas`/`gpuCanvas`/`portalRoot`).
8. **Sello de generación, no barrer.** Los cambios de fuente y zoom invalidan todos los`scaleX`a través de un contador de generación (`ContentProjectionManager.ts:calibrationGeneration`,`calibrationStamp = fontEpoch:pageScaleX`); No toques a todos los transportistas en el momento del golpe. Las células llevan `data-vecto-grid-calib`, por lo que la reutilización deja las líneas intactas.
9. **Preservar la selección en todas las reconstrucciones, pero no durante el arrastre.**`preserveSelectionAcrossRebuild`/`snapshotGridSelection`+`restoreGridSelection`cubren el riesgo de reconstrucción de transmisión; Los arrastres de regiones en blanco tienen autoridad para el navegador y no deben interrumpirse. `releaseSelectionForRebuild`es el hermano más barato cuando el texto seleccionado ya no se proyecta (la ventana se desplaza más allá; deje el`Range`separado en lugar de apuntar a los soportes separados).
10. **Una línea de base, ambos mundos.** Cada cuadro de línea (lienzo y DOM) llama a`Typography.cssLineBoxBaseline()`(`packages/text/src/Typography.ts:cssLineBoxBaseline`). Nunca codifique`0.8 * lineHeight`fuera del nivel alternativo; esa constante es la alternativa, no el contrato.
11. **No midas el medidor.**`style.font`es un captador en vivo (`ContentProjectionManager.ts:292`); lea`data-vecto-grid-font`. Del mismo modo,`getBoundingClientRect`fuerza el diseño: agruparlo (ruta de sonda) y anotarlo (`selectionPresent`/`OverlayGeometry`), no leer por elemento por cuadro.
12. **La virtualización es voluntaria y exclusiva.**`Markdown.virtualize`y streaming`createStream`no componen (`Markdown.ts:614`); `tableViewportHeight`hace (`:652`). Coloque los bloques críticos para la búsqueda dentro de la ventana montada o serán imposibles de encontrar: la materialización, no la profundidad del árbol DOM, decide lo que Ctrl+F puede ver.

### 6.3 Qué cuestan las sondas — no conviertas una comprobación en regresión

-`auditSceneSelection`llama a`getBoundingClientRect`por línea (forzado de diseño) y debe ejecutarse en un navegador real, no en un bucle activo. No lo envíe por la ruta del marco; conéctelo con un interruptor QA o un arnés Playwright.

Instantánea una vez por verificación, no por fotograma.
\-`selectionPresent()`(`ContentProjectionManager.ts:selectionPresent`) es el ejemplo de producción de procesamiento por lotes de la misma lectura: un diseño forzado por recorrido sincronizado, no por elemento. Copie ese patrón para cualquier nueva verificación del estado de la proyección.

## 7. El frame completo — seis pasos, en orden

Para un marco que extiende un bloque de código de transmisión en una línea mientras el usuario tiene una selección en el prefijo sin cambios en DPR 1.6:

1. **Diseño** —`prepareContentGrid`o`LayoutEngine.layoutPrepared`emite el nuevo plan; `Stack`vuelve a medir solo el bloque sucio (`updateTokens`/`virtualHeights`Fenwick).
2. **Canvas sorteo** —`Scene.render`recorre el VMT, aplica `worldTransform × DPR`, emite lotes`fillText`/ `drawImage`. Decisión`flushRun`(`COALESCE_TOLERANCE_PX`) ya preparada.
3. **Sincronización de superposición**:`CanvasGeometry.syncOverlay`alinea`a11yRoot`con `canvasRect`, heredando `fixed`/`absolute` (`CanvasGeometry.ts:206`), memorizado (`OverlayGeometry`).
4. **Materialización** —`syncA11y`/`syncContentProjection`cheque sucio`ContentSyncState`(matriz mundial,`hasBand`/ `visible`,`fontEpoch`/ `viewportEpoch`, `tier`), portadores de ventanas a `hint.minY/maxY`, reutilizar líneas de cuadrícula intactas' `scaleX`, cree intervalos por grafema o intervalos`data-vecto-grid-cell`con `sourceStart/Length/x/advance/level/caretOffsets`.
5. **Preservación de selección**:`ContentProjectionManager.snapshotGridSelection`como desplazamientos de origen,`preserveSelectionAcrossRebuild`/`restoreGridSelection`después de`rebuild()`o`releaseSelectionForRebuild`si el texto seleccionado se desplazó hacia afuera. El arrastre de regiones en blanco sigue estando controlado por el navegador.
6. **Calibración (en frío)**: el cuadro N construye la sonda de 100000 px fuera de la pantalla; el marco N+1 lee`Range`anchos naturales, calcula`scaleX = advance × basisScale / natural`con`basisScale`a partir de una escala de página de 256 px (`ContentProjectionManager.ts:707`), escribe`transform`, estampa`data-vecto-grid-calib`. El estado estacionario es una coincidencia del selector; `vectoGridReady`publicado desde una devolución de llamada de marco.

Cualquier paso que vuelva a medir sin pasar por el paso 1 crea un segundo diseño y una deriva futura. Cualquier paso que lea`style.font`o`getBoundingClientRect`sin pasar por la ruta de memo/atributo paga el costo de 480×/diseño por elemento de §4.
